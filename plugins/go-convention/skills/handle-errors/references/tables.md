# 境界の表と翻訳表

## 応答の表と処理の表

応答の表は、分類から呼び手へ返す Connect の Code を決める。処理の表は、分類ごとに二つの性質を決める。**再処理で通りうるか**は、同じ要求をもう一度処理すれば通る見込みがあるかで、ワーカーと受信境界はこれで再処理させるかを決め、技術的な処理の一件を一時失敗（はい）と恒久失敗（いいえ）のどちらで終えるかも決める。**全体に及ぶか**は、同じ処理の残りの件も同じ理由で失敗するかで、はいなら残りを試さずに打ち切り、いいえなら記録して次へ進む。依存先が落ちているときに全件を試して同じ失敗を件数分出さないためである。

下では読みやすさのために一つの表に並べるが、コードでは応答の表（`rpcerr.Code`）と処理の表（`errors.HandlingOf`）を別の map に持つ。三つ目のログレベルの表は write-logs が持つ。一つの割り当てから別のものを導くと（「WARN の分類は再処理する」のように）、片方を変えたときにもう一方が黙って変わるからである。

| 分類 | Connect の Code | 再処理で通りうる | 全体に及ぶ |
|---|---|---|---|
| 入力が不正 | InvalidArgument | いいえ | いいえ |
| 認証されていない | Unauthenticated | いいえ | いいえ |
| 許可されていない | PermissionDenied | いいえ | いいえ |
| 存在しない | NotFound | いいえ | いいえ |
| すでに存在する | AlreadyExists | いいえ | いいえ |
| 業務ルールに反する | FailedPrecondition | いいえ | いいえ |
| 利用上限に達した | ResourceExhausted | はい | いいえ |
| 未対応の操作 | Unimplemented | いいえ | いいえ |
| 中断された | Canceled | いいえ | はい |
| 同時更新で競合した | Aborted | はい | いいえ |
| 容量の上限を超えた | ResourceExhausted | はい | はい |
| 時間切れ | DeadlineExceeded | はい | はい |
| 依存先が利用できない | Unavailable | はい | はい |
| 回復不能 | Internal | いいえ | いいえ |
| 分類不能 | Internal | いいえ | いいえ |

「回復不能」が全体に及ばないのは、データの破損のように一件に閉じる場合が多いからである。設定の不備のように全体に及ぶものは、起動の時点でプロセスが止まる。「再処理で通りうるか」は物理設計の「やり直し」（一つのトランザクションの中で呼び直すこと）とは別のことで、その回数は `tx.Options` が運ぶ。表に分類が無いときの扱いは、apply-crosscutting-contracts の契約に従う。

## PostgreSQL の翻訳表

`rdb.Translate` が pgx のエラーを写す表である。SQLSTATE の単独のコードと、先頭二桁のクラスで決まる。

| 事象 | 分類 |
|---|---|
| 直列化の失敗（40001）、デッドロック（40P01）、ロックを取れない（55P03） | 同時更新で競合した |
| 接続の例外と切断（08000、08006、08001、08003）、サーバーの停止（57P01、57P02、57P03、57P05）、pgx の切断（`pgconn.ErrConnClosed`、`io.ErrUnexpectedEOF`、閉じたプール）、呼び出し側の ctx が生きているときの接続の確立の失敗 | 依存先が利用できない |
| 資源の不足（クラス53） | 容量の上限を超えた |
| pgx の期限切れ（`pgconn.Timeout`） | 時間切れ |
| 確定の結果が不明（08007、40003）、DB の削除（57P04）、接続を拒まれた（08004）、DB が無い（3D000）、権限の不足（42501）、テーブルが無い（42P01）、認証の失敗（クラス28）、I/O とデータの破損（クラス58、XX） | 回復不能 |
| `Constraints` に載せた一意制約の違反（23505） | 載せた具体エラー |
| 載っていない一意制約の違反、一意以外の制約の違反（クラス23）、プロトコルの違反（08P01）、データの例外（クラス22）、SQL の誤り（クラス42の残り）、読み取り専用での書き込み（25006） | 分類不能（実装の間違い） |
| 問い合わせの取り消し（57014） | ctx が終わっていればその理由、終わっていなければ変えない |
| 行が無い（`pgx.ErrNoRows`） | 存在しない |

一意制約の違反をどの具体エラーへ写すか（資料の拒む理由、「すでに存在する」、「同時更新で競合した」）は、制約を持つリポジトリの `Constraints` が決める。同じ集約の同じ版を二つ積もうとした違反は「同時更新で競合した」を土台にする。どの制約を置くかは物理設計の資料が決める。
