# 運び方、翻訳、付け替え

# 運び方

## 包まずに返す

具体エラーは、分類と文言を自分で持つ。したがって、層を越えるときに `fmt.Errorf` で包まず、そのまま返す。どの操作で起きたかのような文脈は、境界が記録の属性（手続きの名前、リクエストの識別子）で運ぶ。

```go
res, err := loan.Return()
if err != nil {
	return err
}
```

包むのは二つの場面だけである。外部のライブラリのエラーを分類へ写す翻訳と、値の出どころに合わせた分類の付け替えである。

## 一つの連鎖に、分類は一つ

一つのエラーの連鎖が持つ分類は、一つだけにする。二つの分類を持つと、どちらが境界に届くかが照合の順で決まり、意味を失う。このため、次の二つを守る。

分類を付け替えるときは、元のエラーを連鎖から外し、文言だけを残す（下の「付け替え」）。

戻り値に載せる失敗は一つにする。トランザクションの取り消しの失敗や、`Close` の失敗のように、本来の失敗に続いて起きた二つ目の失敗は、本来のエラーに結合せず、注入された logger で記録する。`errors.Join` で二つの失敗を一つの戻り値にしない。

## 判定は `errors.Is` と `errors.AsType`

判定は、分類の package の `errors.Is` で行う。文言を比べない（`err.Error() == ...` や `strings.Contains`）。外部のライブラリの型を見るのは翻訳の中だけで、そこでは `errors.AsType[T]` を使う。usecase やドメインは、外部のライブラリの型を判定しない。

## 捨てない、丸めない

`_ = err` でエラーを捨てない。エラーをゼロ値、既定値、空のスライスに置き換えて続けない。`panic` を書かない。panic の回収は、最も外の境界だけが行う。

失敗の影響を一件に閉じ込めて次へ進む場面（一覧から壊れた一件を除く、巡回で一件の失敗を記録して次へ進む）は、捨てるのではなく、飲み込んだ場所で記録する（write-logs が定める）。どの失敗なら一件に閉じ込めてよいかは、処理の表の「全体に及ぶ」で決める（[境界の表](tables.md)）。

# 翻訳

## 外部のエラーは、翻訳表で分類へ写す

外部のライブラリ（PostgreSQL のドライバ、メッセージの配信基盤、HTTP の外部 API）が返すエラーは、その依存先ごとに一つの翻訳表で分類へ写す。翻訳表は横断的関心事の package（例：`crosscutting/rdb`）に置き、リポジトリや外部境界のポートの実装が呼ぶ。

翻訳は、分類を外側に、元のエラーを内側に置いて包む。元のエラーは連鎖に残るので、記録で原因を辿れる。元のエラーは分類を持たないので、「一つの連鎖に分類は一つ」は保たれる。

```go
func wrap(category error, cause error) error {
	return fmt.Errorf("%w: %w", category, cause)
}
```

翻訳表に無いエラーは、変えずに返す。どの分類にも丸めない。境界がそれを「分類不能」と判定し、翻訳の漏れとして記録するので、記録を見て表に足す。翻訳表は網羅を目指さない。

すでに分類を土台にしているエラーは、もう一度翻訳しない。呼び出し側の中断と期限切れ（`context.Canceled`、`context.DeadlineExceeded`）も、分類の package が別名として扱うので、包み直さない。

## PostgreSQL の翻訳表

pgx が返すエラーは、SQLSTATE と pgx の型で写す。単独で意味が決まるコードと、先頭の二桁のクラスで意味が決まるものがある。

| 事象 | 分類 |
|---|---|
| 直列化の失敗（40001）、デッドロック（40P01）、ロックを取れない（55P03） | 同時更新で競合した |
| 接続の例外と切断（08000、08006、08001、08003）、サーバーの停止（57P01、57P02、57P03、57P05）、pgx の切断（`pgconn.ErrConnClosed`、`io.ErrUnexpectedEOF`、閉じたプール）、接続の確立の失敗 | 依存先が利用できない |
| 資源の不足（クラス53） | 容量の上限を超えた |
| pgx の期限切れ（`pgconn.Timeout`） | 時間切れ |
| 確定の結果が不明（08007、40003）、DB の削除（57P04）、接続を拒まれた（08004）、DB が無い（3D000）、権限の不足（42501）、テーブルが無い（42P01）、認証の失敗（クラス28）、I/O とデータの破損（クラス58、XX） | 回復不能 |
| 名前付きの一意制約の違反（23505）で、その制約がリポジトリの対応に載っているもの | 対応に載せた具体エラー（資料の拒む理由、または「すでに存在する」「同時更新で競合した」） |
| 対応に載っていない一意制約の違反、一意以外の制約の違反（クラス23）、プロトコルの違反（08P01）、データの例外（クラス22）、SQL の誤り（クラス42の残り）、読み取り専用での書き込み（25006） | 分類不能（実装の間違い） |
| 問い合わせの取り消し（57014） | 呼び出し側の ctx が終わっていればその理由（中断、時間切れ）、終わっていなければ変えずに返す |
| 行が無い（`pgx.ErrNoRows`） | 存在しない |

接続の確立の失敗は、呼び出し側の ctx が生きていれば依存先の障害、ctx が終わっていれば呼び出し側の都合として分類する。pgx は接続の期限切れを内部の期限切れとして表すので、ctx で見分ける。

確定を送った後、応答を受け取る前に接続が切れた、期限が切れた、中断されたときは、確定したかどうかが分からない。同じ操作を自動で繰り返すと二重に成立しうるので、再試行を促す分類にせず、「回復不能」として運用者が一次データで確かめる。これはトランザクションの管理が判定する。

データの例外（クラス22）と一意制約の違反の詳細（Detail、Hint）は、入力の値そのものを含みうる。連鎖に残す前に、その文言を落とす。

一意制約の名前から具体エラーへの対応は、制約を持つリポジトリが一つの表（`Constraints`）で渡す。表の値の型を具体エラーに限り、素のエラーを載せられないようにする。

```go
// Constraints は、一意制約の名前から具体エラーへの対応である。例: "loans_book_on_loan_key" → ErrBookOnLoan。
type Constraints map[string]*errors.Error

var loanConstraints = rdb.Constraints{
	"loans_book_on_loan_key": domain.ErrBookOnLoan,
	"loan_base_events_loan_version_key": ErrLoanVersionConflict,
}
```

`ErrLoanVersionConflict` のように、同じ版のイベントを二つ積もうとした違反は、「同時更新で競合した」を土台にする。どの制約を置くかは、物理設計の資料が決める。

# 付け替え

## 値の出どころで、分類を付け替える

値オブジェクトが拒んだエラーは「入力が不正」である。値の出どころが利用者の入力でないなら、出どころの意味で分類し直す。

保存値を復元するときに値オブジェクトが拒んだら、データの破損として「回復不能」にする。設定値を読み込むときに値オブジェクトや名前付きの型が拒んだら、環境の不備として「回復不能」にする。分類を付け替えてよいのは、この原則に当たる場面だけである。

```go
var ErrStoredLoanCorrupted = errors.Define(errors.ErrInternal, "保存された貸出を復元できない")

user, err := vo.NewUserNo(row.UserNo)
if err != nil {
	return nil, fmt.Errorf("%w: 貸出 %s の利用者番号: %v", ErrStoredLoanCorrupted, row.ID, err)
}
```

付け替えるときは、新しい分類の具体エラーを `%w` で包み、元のエラーは `%v` で文言だけ残して、連鎖から外す。元の「入力が不正」を連鎖に残すと、壊れた DB の値が「利用者の入力が不正」として外へ出る。付け替えの書き方は、この一つだけにする。

付け替えは、値の出どころを知っている場所（保存値ならリポジトリと Query の実装の変換、設定値なら設定の読み込み）で一度だけ行う。
