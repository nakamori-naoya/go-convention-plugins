# ログレベル

# レベルの意味

レベルは、運用者に何をしてほしいかで決める。応答の Code や、再処理させるかどうかとは独立に決める。

**DEBUG** は、開発のときだけ要る内訳である。本番の出力の閾値は INFO にし、DEBUG が出る前提の設計にしない。

**INFO** は、正しく拒んだか、記録するだけの出来事である。誰も対応しない。業務上の拒否（業務ルールに反する、存在しない）は、システムが正しく動いた結果なので INFO にする。RPC の完了、巡回の要約、起動と停止もここに入る。

**WARN** は、監視で閾値を設けて見張る対象である。一件ずつはもう一度処理すれば通るが、増えたら容量か依存先を見に行く。同時更新の競合、容量の上限、時間切れ、依存先の一時的な不在がこれに当たる。一件の WARN で人を呼ばない。

**ERROR** は、すぐに人の介入が要るものである。回復不能（データか環境を直すまで解決しない）と、分類不能（実装を直すまで解決しない）がこれに当たる。ERROR を出してよいのはこの二つだけで、「念のため」の ERROR は出さない。業務上の拒否を ERROR にすると、対応が要る行と要らない行が同じ色で並び、ERROR を見る意味が無くなる。

# 分類からレベルへの表

エラーを記録するときのレベルは、エラーの分類（handle-errors が定める15の分類）から、この表で決める。

| 分類 | レベル |
|---|---|
| 入力が不正 | INFO |
| 認証されていない | INFO |
| 許可されていない | INFO |
| 存在しない | INFO |
| すでに存在する | INFO |
| 業務ルールに反する | INFO |
| 利用上限に達した | INFO |
| 未対応の操作 | INFO |
| 中断された | INFO |
| 同時更新で競合した | WARN |
| 容量の上限を超えた | WARN |
| 時間切れ | WARN |
| 依存先が利用できない | WARN |
| 回復不能 | ERROR |
| 分類不能 | ERROR |

表は、ログの横断的関心事の package に一つだけ置き、公開する関数は `Level(err error) (slog.Level, bool)` 一つにする。表に分類が無ければ `false` を返し、既定のレベルへ丸めない。`false` を受け取った境界は、それを表の更新漏れとして扱い、ERROR と `unclassified` の属性で記録する。扱いの理由は、handle-errors の境界の表と同じである。

```go
var levelTable = map[error]slog.Level{
	errors.ErrInvalidInput: slog.LevelInfo,
	// 残りの14行
}

func Level(err error) (slog.Level, bool) {
	level, ok := levelTable[errors.Category(err)]
	return level, ok
}
```

分類不能の記録には、`unclassified` の属性を真で足す。実装の間違いか翻訳の漏れで、実装を直す合図だからである。

表が15の分類を過不足なく持つことは、テストの側に15の分類と期待のレベルを並べた表を持ち、`Level` を通して、分類ごとに `true` が返ることと期待のレベルを一つずつ確かめる。実装の側に、分類の一覧を返す入口を足さない。テストの形は apply-go-test-convention に従う。

# レベルとほかの表の関係

分類から Code への応答の表と、分類から再処理で通りうるかへの処理の表は、handle-errors が持つ。このレベルの表とは別の関心なので、互いに導かない。今の中身では WARN の四つと「再処理で通りうる」の多くが重なるが、それは偶然の一致で、片方を変えてももう片方は変わらない。

# 一件を閉じ込めたときのレベル

巡回や一覧で一件の失敗を記録して次へ進むときも、レベルは同じ表で決める。一件の業務上の拒否は INFO、一件の保存値の破損は ERROR である。巡回のたびに同じ壊れた一件が ERROR になるのは、「人の介入が要る」の意味どおりである。

一覧から壊れた一件を除いた RPC の記録は、RPC 自体が成功していても、除いた一件の記録として ERROR を出す。RPC の完了の行と、除いた一件の行は、別の出来事なので二重の記録ではない。
