# write-logs

[工程順序の定義](playbook.yml)を最初に読み、同じ agent が `steps` を宣言順に実行する。YAML は工程の順序だけを決め、各工程の判断はこの本文と参照資料を読んで行う。失敗した工程は成功扱いせずに止まり、完了した工程、根拠、未決を残す。再開するときは、最初の未完了の工程から続ける。

## 目的

ログを最も外の境界に集め、一度だけ、意味のあるレベルと同じ語彙で出す。読み終えると、どこで記録するか、どのレベルにするか、何を属性に出して何を伏せるかを決められる。

中心にあるのは二つの考えである。一つは、**ログレベルは運用者に求める行動を表す**ことである。ERROR が鳴ったら人が動く、WARN は増えたら見に行く、という意味を保つために、レベルはエラーの分類から表で一意に決める。もう一つは、**記録は一か所で一度**ということである。内側はエラーを返し、境界が拾って記録する。同じ失敗が層の数だけ並ぶと、件数が信用できなくなる。

ログは監査記録の一次データではない。業務の事実はイベントの行が持ち、ログは消えてもよい二次情報である。メトリクスとトレースの代わりにも設計しない。

## 入力

対象のプロセスと、その境界（RPC の interceptor、メッセージ購読の受信境界、ワーカーの巡回、プロセスの起動と終了）を受け取る。

`references` は任意で、追加で従う資料の絶対 path の配列である。手順の最初に読み、この規約と併せて従う。プロジェクト固有の規約（出力先の形式、ログ基盤が解釈するキー）は、対象 repository の AGENTS.md / CLAUDE.md と `references` で渡される。

## 判断基準

### レベルは分類から表で決める

エラーを記録するときのレベルは、handle-errors の15の分類から、[ログレベル](references/levels.md) の表で決める。INFO は正しく拒んだか記録するだけの出来事、WARN は監視で閾値を設けて見張る対象、ERROR はすぐに人の介入が要るものである。ERROR を出してよいのは、回復不能と分類不能の二つだけである。

### 返すなら記録しない、飲み込むなら記録する

エラーを返すなら、記録しない。返したエラーは境界が記録する。エラーを飲み込んで先へ進むなら（一覧から壊れた一件を除く、巡回で一件の失敗を記録して次へ進む）、そのエラーは境界へ届かないので、飲み込んだ場所で一度記録する。どこが境界で、何を記録するかは [記録の場所](references/placement.md) を読む。

### logger は注入する

logger は、プロセスの組み立てで一つ作り、境界の構造体へ引数で渡す。大域の logger（`slog.SetDefault`、`slog.Default()`）に頼らない。ctx に logger を入れない。ctx で運ぶのは、属性の元になる値（リクエストの識別子など）だけである。

### 何を出すかは、記録する行で決める

属性は、固定の語彙のキーと、型付きの helper で渡す。値オブジェクトは、記録する行で値を取り出して渡す。ログの属性は外部の形式への写しなので、プリミティブへ戻してよい。何を出して何を伏せるかは、その行で決める。秘密のキーを伏せる安全網も置く。詳しくは [属性と秘匿](references/attributes.md) を読む。

## 手順

1. **境界を確かめる。** `references` があれば先に読む。対象のプロセスの境界ごとに、記録する場所が一か所に決まっているかを見る。無ければ [記録の場所](references/placement.md) の形で置く。
2. **記録する行を選ぶ。** 書きたい行ごとに、その情報がエラーとして境界へ返るかを問う。返るなら書かない。飲み込むなら書く。ドメイン、リポジトリ、Query の実装では書かない（一覧から壊れた一件を除く Query の実装だけが例外で、除いた場所で記録する）。
3. **レベルを表から決める。** エラーの記録なら、分類から表でレベルを決める。エラーでない記録（起動、巡回の要約）は INFO にする。
4. **メッセージと属性を決める。** メッセージを定型の一文にし、属性を語彙のキーと型付きの helper で書く。秘匿を確かめる。
5. **logger の渡し方を確かめる。** 組み立てで一つ作り、境界へ引数で渡しているか。大域の logger を使っていないか。
6. **機械検査を通す。** `go vet ./...`（slog のキーと値の組の不整合）、`go tool golangci-lint run ./...`（`slog.Default` と `slog.SetDefault` の禁止、ドメインの `log/slog` の禁止）、レベルの表の網羅のテストが通る。
7. **報告する。** 出力の項目を返す。

## 停止条件

ドメイン（値オブジェクト、集約、イベント）にログを求められたら、書かずに止まり、エラーかコマンドの結果で外へ出す設計を返す。エラーを記録して黙って成功を返したい（`return nil`）要求が、一件の失敗を閉じ込める場面に当たらないなら、書かずに `return err` の形を返す。ログを監査記録の一次データにする要求は、イベントの行の設計（データモデルの資料）へ返す。分類から応答や処理を変えたい要求は、handle-errors へ返す。

止まるときは、書いた範囲と書かなかった範囲を分け、返す先と必要な決定を報告に示す。

属性のキーやメッセージの言い回しの揺れでは止まらない。語彙に最も近いものを採り、報告に示して進む。

## 出力

置いた境界と記録の場所、飲み込む場所で書いた記録とその理由、レベルの表の変更、語彙に足したキーと秘匿のキー、logger の渡し方の変更、機械検査の結果、返した論点と返し先を報告する。

機械検査が通って言えるのは、キーと値の組の不整合、大域の logger の使用、ドメインでの `log/slog` の import が無いことと、レベルの表が15の分類を網羅していることだけである。同じ失敗が二行にならないこと、飲み込む場所だけで記録していることは、対象を読んで報告する。
