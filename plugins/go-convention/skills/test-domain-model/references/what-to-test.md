# 何をテストするか

**集約・エンティティ・値オブジェクトのテストは、資料に書かれた判断（生成の条件・事前条件・事後条件・拒む理由・発するイベント）を、メモリ上の値だけで確かめる。** 入力は `Restore*` と `New*` に渡す値と操作の引数、出力は返り値（`Next` / `Event` / `error` / `bool` / VO の値）で、それ以外に観測するものは無い。DB もモックも要らないので、全ケースが並列に走り、1 ケースは 1 ミリ秒で終わる。

## 1. これは何か／何でないか

| これは | これではない |
|---|---|
| 資料の 1 判断を 1 ケースにし、判断の結果（拒む／通る、次の状態、発したイベント）を値で突き合わせるテスト | 集約を保存して読み戻すテスト（永続化層） |
| 状態型のメソッドが「できる操作」だけを公開し、「できない操作」が絞り込みで拒まれることを確かめるテスト | usecase が復元 → 絞り込み → 操作 → 保存を正しい順で呼ぶかのテスト |
| VO の生成の条件と判定の境界（隣接・同時刻）をひとつずつ確かめるテスト | 資料の「同時に起きたとき」を再現するテスト（メモリ上の不変の値に同時実行は無い） |
| 資料の BDD ID をそのまま `id` に持ち、資料の全 ID が `id:` か末尾コメントに現れるテスト | 内部の構造（非公開フィールド・埋め込み struct・定数）を見るテスト |

## 2. テストする／しない

| # | テストする | 何を見るか | 例（題材） |
|---|---|---|---|
| 1 | VO の生成の条件 | 拒む組が sentinel を返し、返り値がゼロ値である。境界の組（`start == end`）がどちら側か。通る組は `New*` を 2 回呼んで `==` で等しい（UTC 正規化） | `TestNewTimeSlot`: 利用終了が利用開始と同時刻 → `ErrTimeSlotNotOrdered` |
| 2 | VO の判定と計算の操作 | 真偽・計算結果と、その境界 | `TestTimeSlot_Overlaps`: 隣接は偽（BDD-013）、一部重なりは真（BDD-014）。`TestHoldDeadline_HasArrived`: 同時刻は到来（BDD-015） |
| 3 | VO を返す操作の New 再生成 | 操作が返す VO が `New*` の結果と等しい | `TestVersion_Next`: `want` は `NewVersion(2)` の結果 |
| 4 | 集約の生成関数 | 事前条件ごとの sentinel、`Next` の値（`Restore*` で組んだ期待と等しい）、発したイベントの値（getter の射影） | `TestHold`: BDD-001 / 010 / 012 と、資格の顧客違い |
| 5 | 集約の操作（遷移） | 事前条件を資料の順に破ったときの sentinel（複数を同時に破ったら最初の理由）、`Next` の値、発したイベントの値、版が 1 進む | `TestTentative_Confirm`: BDD-002 と、期限以降・他人 |
| 6 | 拒まない操作 `(Result, bool)` | 条件を満たさなければ `false` とゼロ値。満たせば `true` と `Next` / `Event` | `TestTentative_Expire`: BDD-005 と、期限前は `false` |
| 7 | 絞り込み関数 | 状態ごとの sentinel、`nil` の sentinel、同じ状態なら同じ値が返る | `TestAsTentative`: BDD-023 と、取消済み・期限切れ・`nil` |
| 8 | 不変条件 | 終端状態に操作が無い（絞り込みが拒む）。`Next` が元の値（予約番号・予約者・利用枠）を引き継ぎ版だけ進む。イベントの版が `Next` の版と一致する | `wantNext` を Given と同じ値から組む。`wantEvent.version` と `wantNext` の版を同じ数にする |
| 9 | 非ルートエンティティ | ルートの操作の `Next` から getter で読む。単独で生成しない | 題材には無い |

| # | テストしない | 理由 | どこが担うか |
|---|---|---|---|
| 1 | getter だけの検証（`Restore*` して `ID()` を読む） | 判断が無い。復元の引数を返すだけ | 誰も書かない |
| 2 | 永続化と復元の往復（保存 → `FindByID` → 同じ値） | 実 DB が要り、marshaller の関心 | 永続化層のテスト |
| 3 | 他の集約の判断（繰上げ判断が受付順の先頭を選ぶ、予約待ちの並び） | この package の要素ではない | 別の集約の package、または usecase |
| 4 | usecase の手順（復元 → 絞り込み → 操作 → 保存の並び、tx の commit / rollback） | 集約は手順を持たない | usecase のテスト |
| 5 | 資料に無い内部（非公開フィールド、共通の埋め込み struct、`holdDuration` のような定数の値そのもの） | 外部テストパッケージから届かず、届いても資料に対応する行が無い | 誰も書かない。定数の効果は判断の境界（15 分後の期限）として現れる |
| 6 | 資料の「同時に起きたとき」（二人の同時仮押さえ） | メモリ上の不変の値に同時実行は無い。集約をまたぐ排他は集約の外 | 永続化層のテスト（DB 制約・2 本並走） |
| 7 | 集約の内側で確かめられない生成の条件（重なる利用枠に有効な予約が無い） | 資料「集約の境界」が生成を呼ぶ側と DB 制約に置いている。`Hold` は `ErrOverlappingSlot` を返さない | 判定は VO のテスト（`Overlaps`）、拒否は永続化層のテスト |
| 8 | ログ、`String()`、JSON | ドメインの package は出さない・持たない | 境界のテスト |

## 3. 観測するもの

テストが観測してよいのは公開 API の返り値だけである。

| 対象 | 観測するもの | しないもの |
|---|---|---|
| 生成関数・遷移 | `got.Next`（状態型の値。`Restore*` で組んだ期待と `assert.Equal`）、`got.Event`（getter の射影を struct にまとめて `assert.Equal`）、`err`（`require.ErrorIs`） | `Next` の非公開フィールド、イベントの型（型引数で決まる） |
| `(Result, bool)` | `ok` と、`true` なら `Next` / `Event`、`false` ならゼロ値 | — |
| 絞り込み | 返った状態型の値と `err` | 型スイッチの内部 |
| VO の `New*` | 返った値と `err`。通る組は `==` | 非公開フィールド |
| VO の操作 | 真偽・計算結果・返った VO | — |

エラー時は結果がゼロ値であることも見る（`assert.Zero(t, got)`）。「エラーと値の両方を返す」実装を検出する。

## 4. ケース数の目安

| 対象 | 資料にあるケース | 資料に無いケースで埋めるもの |
|---|---|---|
| 生成関数 | 表が置いた BDD 全部 | 集約が返す sentinel のうち BDD が無いもの（`ErrEligibilityMismatch`）。事前条件を 2 つ同時に破る組が資料の順で最初の理由を返すこと |
| 遷移 | 表が置いた BDD 全部 | sentinel ごとに 1 つ（期限以降 `ErrHoldDeadlinePassed`、他人 `ErrNotOwner`）。境界（期限と同時刻・利用開始と同時刻）が VO の BDD に置かれているなら、集約側の結果は生成 id のケースで |
| `(Result, bool)` | 表が置いた BDD | `false` 側（条件を満たさない・記録済み） |
| 絞り込み | 表が置いた BDD（状態違いの拒否） | 残りの状態ごとに 1 つ、同じ状態 1 つ、`nil` 1 つ |
| VO の `New*` | 表に無いことが多い | 拒む組ごとに 1 つ、境界 1 つ、通る組 1 つ |
| VO の操作 | 表が置いた BDD | 境界の反対側、対称性（`a.Overlaps(b)` と `b.Overlaps(a)`）、別の会議室 |

「資料にあるケース」を減らさない。「資料に無いケース」は sentinel と境界を埋めたら止める。網羅のために似た値を並べない。
