# 何をテストするか

ドメインのテストは、資料に書かれた判断（受けるか拒むか、次の状態、発するイベント、値の生成の条件）を、メモリの上の値だけで確かめる。入力は、初期状態の型と `Restore*` と `New*` に渡す値と、コマンドの引数である。出力は、コマンドの結果（`Next`、`Event`、error、bool）と、値オブジェクトの値である。DB も mock も要らないので、全ケースが並列に走る。

# テストするもの

**値オブジェクトの生成の条件。** 拒む値が具体エラーを返し、結果がゼロ値であること。境界の値がどちら側か。通る値は、`New*` を二回呼んで `==` で等しいこと（UTC への正規化）。

**値オブジェクトの判定と計算。** 真偽と計算の結果と、その境界。返却期限の当日はまだ過ぎていない、翌日は過ぎている、のような資料の境界を、両側で確かめる。

**生成のコマンド。** 初期状態の型のコマンドが、持っている材料（貸出状況）で受けるか拒むかを決めること。拒むなら資料の拒む理由の具体エラー、受けるなら版1の `Next` と `Event`。複数の理由を同時に破ったときに、決めた順の最初の理由が返ること。

**保存された状態のコマンド。** 和型のコマンドを、状態ごとに確かめる。受ける状態では、`Next` の値、`Event` の値、版が一つ進むこと。受けない状態では、資料の拒む理由の具体エラー。和型のコマンドを状態の数だけ確かめるので、「受けない状態が資料の理由を返す」ことがテストに現れる。

**拒まないが何も変えないコマンド。** 条件を満たさなければ `false` とゼロ値、満たせば `true` と `Next` と `Event`。

**変わらない値。** `Next` が識別子、利用者、本、返却期限を引き継ぎ、版だけが進むこと。`Event` の版が `Next` の版と一致すること。これは、受けるケースの `wantNext` と `wantEvent` の中で確かめる。

# テストしないもの

値を取り出す関数だけのテスト（`Restore*` して `ID()` を読む）は書かない。判断が無いからである。

永続化と復元の往復、DB の制約が守る決まり（一冊の本が同時に一つの貸出にしか属さない）、同時に起きたとき（同じ利用者が同時に借りる）は、永続化層のテストが主に担う。メモリの上の不変の値には、同時実行が無い。

材料を集めること（利用者の貸出状況を読むこと）は、永続化層のテストが主に担う。ドメインのテストは、初期状態の型に材料を直接渡す。

手順（見つける、コマンドを呼ぶ、適用する、トランザクション）は、usecase のテストが主に担う。本人の確認（他人の利用者カード）は、handler のテスト（API のテスト）が主に担う。

非公開のフィールド、埋め込んだ struct、業務の数の定数の値そのものは、テストしない。定数の効果は、判断の境界（14日後の返却期限、5冊の上限）として現れる。

# 観測するもの

観測してよいのは、公開 API の返り値だけである。コマンドの結果の `Next` は、`Restore*` で組んだ期待の値と `assert.Equal` で比べる。`Event` は、取り出しの関数の値を並べた射影の struct にまとめて比べる。エラーは `require.ErrorIs` で確かめ、そのとき結果がゼロ値であることも見る。「エラーと値の両方を返す」実装を見つけるためである。

# ケースの数

資料の BDD のうち、ドメインのテストが主に担うものは、すべて書く。資料に無いケースは、具体エラーごとに一つ以上、境界の両側、理由を同時に破る組の順、拒まないコマンドの `false` 側を埋めたら止める。網羅のために似た値を並べない。
