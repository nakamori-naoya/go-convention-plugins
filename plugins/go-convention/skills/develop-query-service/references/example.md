# 例：図書館の延滞の一覧

図書館の貸出のクエリデータモデルと物理設計の見本の資料を写した、延滞の一覧を返す Query の実装の要の部分と、そのテストで置く行の判断である。写すのは判断の形で、テーブル、列、読み取りの番号は対象の資料から取る。

## 壊れた一件を除く

```go
for _, row := range rows {
	item, err := loanRowToSummary(row)
	if err != nil {
		// row は DB の生成型の行である。保存値が壊れているので、保存された値のまま記録する。
		q.logger.LogAttrs(ctx, slog.LevelError, "保存値の壊れた貸出を一覧から除いた",
			slog.String("loan_id", row.LoanID.String()), slog.Any("err", err))
		continue
	}
	items = append(items, item)
}
```

## 返してはいけない行

基準日の時点で、ある利用者が延滞している貸出を返す Query なら、実装の条件は「その利用者の」「まだ返していない」「返却期限が基準日より前」の三つである。どのケースにも共通の Before として、持ち主の書き込み経路で次の行を置く。別の利用者が延滞している貸出、同じ利用者の、延滞してから返した貸出、同じ利用者の、返却期限が基準日ちょうどの貸出である。最後の行は閾値の返らない側で最も近い値で、条件が「基準日以前」だったら一日後の期限の貸出に替わる。期限が基準日の前日の貸出は返る側の境界なので、共通の Before には置かず、それを確かめるケースの Given に置く。どの条件にも関係しない、別の利用者が別の本を借りている貸出も置く。

条件を一つずつ外すと、どのケースも赤になるはずである。たとえば「まだ返していない」を外すと、延滞してから返した貸出が混ざる。赤にならない条件があれば、共通の行が足りないか、その条件が取得結果を変えないかを見分ける。貸出中の状態と、返却の日時が空であることの両方で絞っていて、片方を外しても結果が変わらないのは後者で、行を足さずに理由を報告に書く。

## 並びとページ

延滞の一覧を返却期限の古い順に返し、同じ期限の貸出は貸出の識別子の順に並べると資料が決めているなら、並びのケースの Given では、期限の新しい貸出を先に、古い貸出を後に書き込み、同じ期限の貸出を二件置く。書き込む順と返す順が逆なので、並びの SQL が抜けると赤になり、同じ期限の二件で同順位の扱いを確かめられる。一回に返す件数が二件なら、ページのケースでは三件目の境界の前後に貸出を置き、二件目が壊れた一件のときも、次の目印が二件目の走査の後になり、次のページが三件目から始まることを確かめる。
