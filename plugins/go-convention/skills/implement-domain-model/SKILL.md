# implement-domain-model

[工程順序の正本](playbook.yml)を最初に読み、同じagentが\`steps\`を宣言順に実行する。YAMLは工程順序を決め、各工程の判断内容と根拠はこの本文と参照資料を実読して評価する。失敗時は成功扱いせず停止して、完了工程、根拠、未決を残し、再開時は最初の未完了工程から続ける。

これは、**domain-model 資料に書かれた要素・操作・拒む理由を、そのまま Go の型・メソッド・sentinel に写す規約**である。資料の 1 要素が 1 つの型、1 操作が 1 つのメソッド、拒む理由 1 行が 1 つの sentinel になり、資料に無いものは作らない。

これは、**業務を発見したりモデルを設計したりするもの**ではない。何を集約にし、どの操作を持たせ、何を拒むかは資料が決めていて、ここでは決めない。資料に無いこと（要素、操作、状態、拒む理由）が実装に要ると分かったら、書かずに資料へ返す。永続化（テーブル・SQL・行との変換）、トランザクション、複数集約の協調、RPC の DTO、ログ、エラーの翻訳表、テストも扱わない。ドメインの package はそれらの package を import しない。

前提: Go 1.27。標準ライブラリだけ（`errors` / `time` / `context` / `slices`）。外部ライブラリを使わない。

## 規約

| # | 柱 | 一言で | 正本 |
|---|---|---|---|
| 1 | 値オブジェクト | 非公開フィールドの struct。`NewX(...) (X, error)` は拒む組があるときだけ `error`。ゼロ値は無効。`==` で比べられるよう New で正規化（time は UTC）。`String()` を書かない | [value-object.md](references/value-object.md) |
| 2 | 集約と typestate | 状態ごとの型と封じた和型。操作は状態型の値レシーバで `(Transition[Next, Event], error)`。拒まないが変えない操作は `(Result, bool)`。絞り込み `As*`、復元 `Restore*`。拒む理由は sentinel。時刻と ID は引数。永続化ポートは集約の package に 1 つ | [aggregate-typestate.md](references/aggregate-typestate.md) |
| 3 | ドメインイベント | 集約ごとに封じた和型。1 操作 1 イベントを遷移結果型で返す。版と発生時刻を持つ。状態名と衝突すれば `Event` 接尾辞 | [events.md](references/events.md) |
| 4 | 資料からの導き方 | 要素 → 型、持つもの → フィールド、生成の条件 → `New` / 生成関数、操作 → メソッド、拒む理由 → sentinel、状態と型の分割 → typestate。資料に無いコマンドを作らない。許す例外は `Restore*` / `As*` / getter / 遷移結果型 / イベント型の版 | [from-domain-model-doc.md](references/from-domain-model-doc.md) |
| 5 | 題材の完全な例 | 貸会議室予約の集約「予約」を写した package `reservation` の全コード | [example-reservation.md](references/example-reservation.md) |

### する／しない

| する | しない |
|---|---|
| 資料の要素を VO・状態型・イベント型に写す | 資料に無い要素・状態・操作・拒む理由を足す |
| 生成の条件を `NewX` / 生成関数で確かめ、拒む組に sentinel を返す | 生成の条件の判断を実行時の既定値や `Validate()` で代用する |
| 資料の操作を状態型のメソッドにし、事前条件を資料の順に確かめる | 共通 interface に全コマンドを置き、できない状態にスタブを書く |
| 拒む理由 1 行に sentinel 1 つ、日本語の文言、行末コメントに資料の語 | `panic`、`fmt.Errorf` で作る場当たりのエラー、`error` の文言の比較 |
| 時刻と ID を操作の引数で受ける | `time.Now()`、採番、乱数 |
| 集約と同じ package に永続化ポートの interface を置く | リポジトリの実装、SQL、行との変換、トランザクション |
| 他の集約の状態を「判断に要る値」として引数で受ける | 他の集約を持つ、リポジトリを集約に渡す |
| 資料の数（15 分・30 日）を非公開定数にする | 業務の数をリテラルで式に埋める |

## 手順

1. **資料を読み、対応表を作る。** domain-model 資料の要素一覧・各要素の詳細・状態と型の分割・ドメインイベントを読み、要素ごとに Go の型名、操作ごとにメソッド名と返り値の形、拒む理由ごとに sentinel 名を表にする（[example-reservation.md](references/example-reservation.md) 冒頭の表の形）。完了条件: 資料の要素・操作・拒む理由の全行に Go の名前が付き、資料に無い名前が表に無い
2. **値オブジェクトを書く。** 識別子、資料の VO の順。「持つもの」をフィールド、「生成の条件」を `NewX`、「操作」を判定・計算メソッドにする。完了条件: 全 VO が非公開フィールド・`NewX`・getter を持ち、`error` を返すのは拒む組があるものだけ
3. **集約を書く。** 「状態と型の分割」から和型・状態型・部分和型を書き、`core` と状態型にフィールドを分け、「操作: X」ごとにメソッドを置く。事前条件は資料の順、事後条件は `Next`、発するイベントは `Event`。完了条件: 状態型の数が資料の「分ける」の数と一致し、各状態型のメソッドが「できる操作」の列と一致する
4. **sentinel とイベントを書く。** 「拒む理由」と「生成の条件」から sentinel、「発するイベント」からイベント型。完了条件: sentinel の行末コメントから資料の行へ戻れ、イベント型の数が資料の表の行数と一致する
5. **絞り込み・復元・永続化ポートを書く。** 状態の数だけ `As*` / `Restore*`。データモデル資料がイベント系テーブルを持つならイベント型、無ければ通常型の interface。完了条件: `FindByID` が和型を返し、状態指定の取得が無い
6. **機械検査を通す。** 完了条件: 次が全部通る
   ```bash
   gofmt -l ./<domain package>        # 出力なし
   go vet ./<domain package>/...
   ! go list -deps ./<domain package> | grep -E 'log/slog|jackc/pgx|connectrpc|database/sql'   # ドメインが境界の package を import していない
   ```
7. **報告する。** 下の「報告」の項目

## 停止条件

- domain-model 資料が無い、または「各要素の詳細」「状態と型の分割」の節が無い → 書かない。資料の作成へ返す
- 資料の操作に「事前条件」「事後条件」「拒む理由」「発するイベント」のどれかが無い → その操作を書かない。資料の書き手へ、欠けている項目を挙げて返す
- 資料の「未決」が実装に要る（未決の操作を呼ぶ、未決の値を持つ） → 書かない。未決の行を挙げて返す。既定値で埋めない
- 資料の「生成の条件」に、集約の内側では確かめられない条件があり、「集約の境界」にその守る場所が書かれていない → 生成関数を書かない。資料へ返す
- 資料に無い操作・状態・拒む理由が要ると分かった → 書かずに、何が要るかと資料のどこに書くべきかを返す
- 永続化の型（通常型／イベント型）を決めるデータモデル資料が無い → 永続化ポートの interface を書かずに止まり、集約・VO・イベントまでを報告する

## チェックリスト（機械で言えないことだけ）

- [ ] 資料の要素・操作・拒む理由・イベントの全行に Go の名前があり、対応表から逆引きできる
- [ ] 資料に無い公開メソッド（状態を変えるもの）が無い。`Set*` / `Update*` / `Can*` / `Validate*` / `Bulk*` が無い
- [ ] VO のフィールドが全部非公開で、`type X string` のような defined basic type を VO と呼んでいない
- [ ] `NewX` が `error` を返すのは拒む組があるものだけ。ゼロ値に意味を持たせていない
- [ ] 状態型の数が「状態と型の分割」の「分ける」の数と一致し、終端状態にメソッドが無い
- [ ] 全メソッドが値レシーバで、レシーバのフィールドを書き換えていない
- [ ] 遷移は `(Transition[Next, Event], error)`、拒まない操作は `(Result, bool)`。返り値が 3 つ以上のメソッドが無い
- [ ] 事前条件の `if` の並びが資料の「事前条件」の順と同じで、型が保証する条件を実行時に確かめていない
- [ ] sentinel の文言が日本語・句点なし・「何が拒まれたか」で、行末コメントに資料の語がある。資料に無い sentinel は別の var ブロックにあり、資料に無いとコメントがある
- [ ] `time.Now()`・採番・乱数・`panic`・`String()`・`log/slog` が無い
- [ ] 永続化ポートの `FindByID` が和型を返し、`Delete` と一覧・件数のメソッドが無い

## 報告

- 資料と Go の対応表（要素・操作・拒む理由・イベント → 型・メソッド・sentinel）
- 書いた package と型の一覧、永続化ポートの型（通常型／イベント型）とその根拠（データモデル資料のどの節か）
- 資料にあって書かなかったもの（停止条件に当たったもの）と、資料へ返す問い
- 資料に無く置いたもの（`Restore*` / `As*` / `Version` / 資料に無い sentinel）の一覧
- 機械検査の結果（`gofmt` / `go vet` / import の検査）
