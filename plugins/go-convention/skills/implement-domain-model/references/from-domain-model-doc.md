# 資料からの導き方

**Go のドメインモデルは、domain-model 資料を型へ写したものである。資料に書かれた要素・操作・拒む理由だけを書き、資料に無いものを足さず、資料にあるものを落とさない。** 資料の節ごとに、Go の何になるかが決まっている。

## 1. 節ごとの対応

| 資料の節 | Go |
|---|---|
| 要素一覧の「種別」 | 値オブジェクト → 非公開フィールドの struct と `NewX`（[value-object.md](value-object.md)）。集約ルート → 和型と状態型（[aggregate-typestate.md](aggregate-typestate.md)）。ドメインイベント → イベント型（[events.md](events.md)） |
| 要素一覧に載らない識別子（予約番号・予約者・会議室） | 識別子の VO。集約自身の識別子は `ID`、他は資料の語 |
| 各要素の「持つもの」 | フィールド。「〜のときだけ」持つものは、その状態型だけのフィールド |
| 各要素の「不変条件」 | 型の形で守る（生成後に変わらない・状態型にメソッドが無い）か、`NewX` の検査。実行時に毎回確かめる `Validate()` にしない |
| 各要素の「生成の条件」 | VO は `NewX`。集約は生成の package 関数（`Hold`）。「揃わない組は存在しない」と書かれた組が sentinel |
| 「協働相手」 | 引数で受ける値（`Eligibility`）と、イベントの受け手。他の集約を持たず、識別子で指す |
| 「操作: X」の見出し | 状態型のメソッド（または生成関数）。名前は資料の語の動詞。1 見出しに 1 メソッド |
| 操作の「事前条件」 | 「〜である」（状態）は型が保証。残りは資料の順に `if` で確かめる |
| 操作の「事後条件」 | 遷移結果型の `Next`。「〜になり、〜は変わらず」を新しい状態型の値で写す |
| 操作の「拒む理由」 | 1 行に sentinel 1 つ。「なし（〜でなければ何も変えない）」は `(Result, bool)` |
| 操作の「発するイベント」 | 遷移結果型の `Event`。1 操作 1 イベント |
| 「状態と型の分割」の表 | 「分ける」→ 状態型を 1 つ。「できる操作」→ その型のメソッド。「できない操作」→ メソッドが無い（絞り込み関数が sentinel を返す）。「分けない」→ 1 つの型で値の違い |
| 「集約の境界」の「外への参照」 | 識別子のフィールド。「値で受け取る」→ 操作の引数 |
| 「集約をまたぐ不変条件」 | 集約の内側には書かない。「守る場所」が生成を呼ぶ側なら、その sentinel は集約の package に置くが集約は返さない（`ErrOverlappingSlot`） |
| 「ドメインイベント」の表 | 「発する要素・操作」の行ごとにイベント型。「始まる判断」はドメインに書かない（usecase の関心） |
| 「拒むときの理由」（業務知識の正式な定義の表） | sentinel の一覧。文言は「何が拒まれたか」、行末コメントに資料の語 |

## 2. 資料にあって Go に写さないもの

| 資料の節 | 扱い |
|---|---|
| 「BDD との対応」 | テストの関心。実装はこの表を読まない。ここから実装の分岐を増やさない |
| 「捨てた割り当て」 | 書かない。捨てた案の型（顧客の集約・会議室の集約・予約待ち列）を作らない |
| 「未決」 | 書かない。「決まるまで操作を置かない」と書かれたものは置かない。未決を既定値や `TODO` で埋めない |
| 「この資料に書かないもの」 | 永続化・層構成・DTO・排他方式はこの skill の外。ドメインの package はそれらの package を import しない |
| 「モデル図」 | 読み物。図に描かれた矢印から型を作らない（型は要素一覧と各要素の詳細から作る） |

## 3. 資料に無いものを作らない

**資料に無いコマンド（状態を変える公開メソッド）を作らない。** 「あると便利」「将来使う」「対称性のため」は理由にならない。次だけは資料に無くても置く。

| 許す | 理由 |
|---|---|
| `Restore*` | 永続化からの復元。資料は永続化を書かない |
| `As*`（絞り込み関数） | 和型から状態型へ。資料「できない操作」の拒否を担う |
| getter | 資料「持つもの」を読む。状態を変えない |
| 遷移結果型 `Transition` と操作ごとのエイリアス | 返り値を 2 つに収める Go の都合 |
| イベント型の版 `Version` | イベント型の永続化の楽観ロックに要る |
| `Version` VO と `NewVersion` | 上の版を表す |
| 資料に無く Go の型の都合で要る sentinel（VO の生成の条件、和型の nil） | 別の var ブロックに置き、資料に無いことをコメントに書く |
| 資料の「協働相手」が渡す値を集約の外で組み立てるための VO の `New`（`NewEligibility`） | 資料「生成の条件」そのもの |

資料にあるのに Go に無いものも作らない。資料の操作を「実装しにくい」で省かず、資料へ返す（[SKILL.md](../SKILL.md) 停止条件）。

## 4. 手順の見取り図

1. 要素一覧を上から読み、種別ごとに型の名前を決める（識別子 → `ID` / `CustomerID` / `RoomCode`、VO → `TimeSlot` …、集約 → 状態型 4 つ、イベント → 5 つ）
2. VO を「持つもの」「生成の条件」「操作」から書く。生成の条件に拒む組があるものだけ `error`
3. 集約の「状態と型の分割」から和型・状態型・部分和型を書き、「持つもの」を `core` と状態型のフィールドに分ける
4. 「操作: X」ごとに、置き場（生成関数か、どの状態型か）と返り値（`(Result, error)` か `(Result, bool)`）を決めて書く。事前条件は資料の順
5. 「拒む理由」と「生成の条件」から sentinel を書き、行末コメントに資料の語を置く
6. イベント型を書き、各操作の `Event` に入れる
7. `As*` と `Restore*` を状態の数だけ書く
8. 永続化ポートの interface を書く（データモデルがイベント系テーブルを持てばイベント型、無ければ通常型）
9. 資料の要素・操作・拒む理由を 1 つずつ Go の名前と突き合わせ、対応表を作る

## 5. 題材での対応

| 資料 | Go | 備考 |
|---|---|---|
| 利用枠・操作「重なるか」 | `TimeSlot.Overlaps` | 半開区間。隣接は偽 |
| 仮押さえ期限・操作「到来したか」 | `HoldDeadline.HasArrived` | 同時刻は到来。`NewHoldDeadline(heldAt)` が 15 分後を導く |
| 顧客の予約資格・操作「新しい申込みができるか」 | `NewEligibility` / `Eligibility.CanApply` | 生成の条件が導出の規則そのもの |
| 予約・操作「仮押さえ予約を成立させる」 | `Hold` | 「重なる利用枠」は集約の外。`ErrOverlappingSlot` は呼ぶ側と DB 制約の翻訳が返す |
| 予約・操作「確定する」 | `Tentative.Confirm` | 「確定済み予約の再確定」は `AsTentative` が返す `ErrAlreadyConfirmed` |
| 予約・操作「取り消す」 | `Tentative.Cancel` / `Confirmed.Cancel`（`Active` 経由） | 取消済み・期限切れは `AsActive` が拒む |
| 予約・操作「期限到来を反映する」 | `Tentative.Expire` → `(ExpireResult, bool)` | 拒まない |
| 予約・操作「無断不利用を記録する」 | `Confirmed.RecordNoShow` → `(NoShowResult, bool)` | 拒まない。状態は変わらず版は進む |
| 状態と型の分割（予約） | `Tentative` / `Confirmed` / `Cancelled` / `Expired` | 4 つとも「分ける」 |
| 状態と型の分割（顧客の予約資格） | `Eligibility` 1 つ | 「分けない」 |
| ドメインイベント（予約の 5 つ） | `Held` / `ConfirmedEvent` / `CancelledEvent` / `ExpiredEvent` / `NoShowRecorded` | 予約待ちの 3 つは別の集約 |
| 予約待ち集約 | この例には無い | 別の package `waitlist` として同じ形で書く |
