# 集約

集約は、状態ごとに別の型を持つ不変の値である。usecase は、集約を見つけ、コマンドを一回呼び、結果を適用するだけにする。そのために、集約の側に次の形を置く。完全な例は [例：図書館の貸出](example-library.md) にある。

# 型の形

## 初期状態の型

まだ保存されていない集約は、**初期状態の型**で表す。生成のコマンドの受け手である。初期状態の型は版を持たない。版0や「版なし」を表す特別な値は作らない。保存されていないことを、型そのものが表すからである。

初期状態の型の名前は、資料にその状態の語があればそれを使う。無ければ、名前を資料への提案に含める。`New` の接頭辞は生成関数の名前に使うので、型の名前には使わない。

## 保存された状態の型と、その和

状態遷移図の状態一つに、保存された状態の型一つを置く。保存された状態の型は、コマンドを持たない終端の状態も含めて、どれも版を持つ。永続化するときに、現在の行の版と一致させるためである。

保存された状態の型の和は、非公開のメソッドを一つ持つ interface で閉じ、宣言に `//sumtype:decl` を付ける。**和型は、保存された状態が受けうるすべてのコマンドを持つ。** どの状態でそのコマンドを受け、どの状態で拒むかは、状態ごとの型が決める。こうすると、usecase は状態の型を調べずにコマンドを呼べる。コマンドを一つ足したときに、すべての状態が受けるか拒むかを決めることを、コンパイラが強いる。

受けない状態のメソッドは、資料の拒む理由を返す。資料にその理由が無ければ、そのコマンドを和型に置かずに止まる（[資料の読み方](reading-the-model.md)）。

どの状態でも変わらない値（識別子、ほかの集約への参照、版）は、非公開の struct にまとめ、状態の型が埋め込む。同じ振る舞いを複数の状態が持つなら、非公開の関数に一つだけ書き、状態の型から呼ぶ。

## 復元

保存された状態の型は、`Restore<状態名>(...)` で組み立て直す。検証しないので error を返さない。値オブジェクトの検証は、行から値オブジェクトへの変換がすでに済ませている。`Restore*` を呼ぶのは、リポジトリとテストだけである。usecase は呼ばない。

# コマンド

## 形

コマンドは、状態の型の値レシーバのメソッドで、`<コマンド名>Result` と error を返す。`<コマンド名>Result` は、次の状態の型 `Next` と、発するイベント `Event` を持つ具体の struct である。次の状態の型に操作が無くても、この形を崩さない。

```go
type ReturnResult struct {
	Next  ReturnedLoan
	Event Returned
}
```

コマンドは、現在の版を一つ進めた値を、次の状態とイベントの両方へ渡す。生成のコマンドは、版1を渡す。版を決めるのはコマンドだけで、リポジトリはイベントの版を写すだけにする。

拒まないが何も変えないことがあるコマンド（資料が「拒む理由は無く、条件を満たさなければ何も変えない」と書くもの）は、`(Result, bool)` を返す。何も起きなかったことは失敗ではない。

## 判断はコマンドの中に置く

事前条件は、コマンドの中で資料の順に確かめ、最初に破れた理由を返す。資料が順を決めていなければ、その順を仮置きし、報告で示す。「〜の状態である」という事前条件は、メソッドがその状態の型にあることで満たされるので、`if` を書かない。

判断だけの公開メソッド（`CanBorrow`、`IsOverdue`、`Validate`）を置かない。呼ぶ側が先に判断して、その結果でコマンドを選ぶ形は、業務の判断を usecase へ漏らす。判断だけを使う BDD が資料にある場合に限り、独立した判断を置く。

公開メソッドは、コマンドと、呼び手が実際にある値の取り出しの関数だけにする。

## 集約の外の事実は、初期状態の型が持つ

コマンドの判断に集約の外の事実（利用者のほかの貸出の数）が要るなら、それは初期状態の型が持つ（[資料の読み方](reading-the-model.md) の引数の対応）。コマンドの引数では受けない。保存された状態の型へは引き継がない。

## 時刻と識別子

ドメインは Clock を持たず、採番もしない。業務の時刻は時点の値オブジェクトで、採番した識別子は値オブジェクトで、コマンドの引数に受ける。業務の数（貸出の期間、貸出の上限）は、package の非公開の定数にする。

## ドメインは外を知らない

ドメインの package は、`log/slog`、永続化、入口のプロトコル、JSON の package を import しない。記録、永続化、表現は、それぞれの境界の関心である。

# イベント

イベントは、コマンドが成立したことを表す不変の値で、コマンドの結果の `Event` として一つ返る。資料のイベント一つが、Go のイベントの型一つになる。名前は資料のクラス図の英名にする。状態の型と名前が衝突するなら、状態の型の側に語を足す（`OverdueLoan` と `Overdue`）。

イベントは版を持つ。業務の時刻を引数で受けるコマンドのイベントは、その時点を持つ。イベントが持つ値の列は、データモデルの資料のイベント表から決める。値の取り出しの関数は、リポジトリの Apply が実際に読むものだけを置く。

イベントを作るのはコマンドだけである。イベントの生成関数を公開しない。

# 永続化ポート

集約と同じ package に、集約ごとに一つの interface を置く。「interface は使う側で定義する」の例外である（write-go-code が定める）。

メソッドは、完全な集約を一つ返す Find と、イベントを永続化する `Apply<イベント名>` だけを基本にする。Find の名前は返す型で決める（和型なら `FindLoan`、初期状態の型なら `FindPendingLoan`）。識別子が複数の値の組なら、その値オブジェクトを並べて受ける。一覧、件数、存在の確認は置かない。それは読み取りの口で、Query の側に置く。

`Apply<イベント名>` は error だけを返す。保存した結果を詰め直した構造体を返さない。usecase の出力は、コマンドの結果から作る。

Find の中で何をどう読むかと、Apply が何を書くかは、implement-repository が決める。
