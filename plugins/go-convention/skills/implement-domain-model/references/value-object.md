# 値オブジェクト

値オブジェクトは、非公開フィールドの struct を `New*` だけが作り、生成の後に変わらず、`==` で比べられる値である。資料の値の不変条件は、`New*` の検査と型の形で守る。同じ値なら同じもので、同一性を持たない。

# 形

フィールドはすべて非公開にする。値が一つでも `struct{ v string }` にする。`type UserNo string` のような defined basic type は、型変換で生成の条件を迂回できるので使わない。

`New*` は、生成の条件で拒む値があるときだけ `(X, error)` を返し、無ければ `X` を返す。拒む値が無いのに error を返すと、呼ぶ側に決して起きない分岐が増える。拒むエラーは、値の構造として必ず拒む値なら「入力が不正」を土台にする（handle-errors が定める）。

ゼロ値は無効で、意味を持たせない。「未設定」が業務上要るなら、状態の和か `(T, bool)` で表す。

`New*` で正規化し、`==` で比べられる値にする。時点は `UTC()` にする。文字列の正規化は、資料に規則があるときだけ行う。`Equal` を書かない。

生成の後に変わらない。値を変える操作は、`New*` を通して新しい値を返す。生成の条件を二か所に書かないためである。

値の取り出しは、値が一つなら `Value()`、複数なら資料の語の名前にする。`Get` を付けない。取り出しの関数は、呼び手が実際にあるものだけを置く。

`Restore*` は、`New*` が引数から値を導く（引数と持つ値が違う）ときだけ置く。返却期限を貸出の時点から導く `DueFrom` なら、期限の日そのものから戻す `RestoreDue` が要る。

# 実装しないもの

値オブジェクトは、`String()`、`slog.LogValuer`、`MarshalJSON`、`Scan`、`driver.Valuer`、`IsValid()`、`Validate()` を実装しない。

`String()` と `slog.LogValuer` を実装すると、`%v`、`fmt.Errorf`、ログを通して、書いた人が意図しない場所で中身が出る。何を記録に出すかは、記録する行で値を取り出して決める（write-logs が定める）。永続化と表現の形は境界の関心で、ドメインの package はそれらを import しない。生成の条件は `New*` の中にあり、生成の後の値は常に有効なので、検証のメソッドは要らない。

# 識別子

識別子は、型ごとに別の struct にする。`LoanID` と `UserNo` を取り違えると、コンパイラが止める。識別子の元になる UUID は、採番器が業務の概念を持たない値として返し、使う側がその場で識別子の値オブジェクトへ変換する。`New*` は、与えられた値を検査するだけで、採番しない。

# 取りうる値が有限なもの

状態、種別、方式のように取りうる値が有限なら、封じた型（非公開フィールドの struct と package 変数）にする（write-go-code が定める）。集約の状態は、値ではなく型で分ける（[集約](aggregate.md)）。

# 導出される値

資料で「〜から決まる値」と書かれたものは、材料を受け取って `New*` の中で決める。決め方が生成の条件そのものである。材料を集めるのは呼ぶ側である。業務の数は、package の非公開の定数にし、式にリテラルを埋めない。

# 境界の向き

時点の比較は `Before`、`After`、`Equal` で行う。「返却期限の当日は、まだ過ぎていない」のような境界は、資料の文をそのまま条件にし、向きをコメントに書く。
