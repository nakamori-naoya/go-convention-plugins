# 資料の読み方

Go のドメインモデルは、資料を型へ写したものである。資料に書かれたものだけを書き、資料に無いものを足さず、資料にあるものを落とさない。

読む資料は二つある。**業務知識の資料**は、拒む理由の正本である（「拒むときの理由」）。**ドメインモデルの資料**は、集約、値オブジェクト、イベントと、状態とコマンドを図で示し、どのコマンドがどの理由で拒むかを示す。図の形は model-domain（W1）が決め、これからも変わりうるので、ここでは節の見出しの形に頼らず、何を読むかで書く。

# 図から読むもの

**クラス図**から、要素とその種類を読む。ステレオタイプが、Go の型の種類を決める。`<<集約ルート>>` は集約の型（初期状態の型、保存された状態の型、その和）になる。`<<値オブジェクト>>` は値オブジェクトになる。`<<値オブジェクト・文脈共有>>` も値オブジェクトで、置き場を apply-go-package-layout が決める。`<<ドメインイベント>>` はイベントの型になる。集約ルートの操作の行（`+本を借りる(利用者番号, 資料番号, 貸出日, 貸出状況)`）から、コマンドとその引数を読む。

**状態遷移図**から、状態と、どのコマンドがどの状態を受けてどの状態へ移すかを読む。状態一つが、保存された状態の型一つになる。`[*]` から出る矢印のコマンドは生成のコマンドで、初期状態の型が持つ。それ以外の矢印のコマンドは、保存された状態の和型が持つ。

# 文から読むもの

図に無いものだけを、文から読む。拒む理由（受けない状態から呼ばれたときの理由を含む）と、事前条件の業務上の条件である。

拒む理由の正本は、業務知識の「拒むときの理由」である。ドメインモデルの文は、どのコマンドが、どの状態で、その理由で拒むかの対応を示す。理由一つに具体エラー一つを定義する（handle-errors が形を決める）。

「守ること」の文は、値オブジェクトの生成の条件と、変わらない値の根拠になる。「取り違えやすいもの」の文は、型に持たせないもの（貸出状況を保存された貸出へ引き継がない、など）の根拠になる。

# 資料の引数と、Go のメソッドの引数

資料のコマンドの引数と、Go のメソッドの引数は、次の規則で対応させる。この対応はここだけで決め、ほかの skill はこれに従う。

資料の引数のうち、**集約の外の事実の写し**（貸出状況のように、利用者のほかの貸出から集めた値）と、**それを読むための識別子**（利用者番号、資料番号）は、初期状態の型が持つ。リポジトリの Find が、それらを読んで値にし、初期状態の型へ持たせて返す。Find は読むだけで、判断しない。上限に達しているかを見て拒んだり、読み方を変えたりしない。拒むのは、初期状態の型のコマンドである。

資料の引数のうち、**業務の時刻**と、**採番した識別子**は、メソッドの引数に残る。業務の時刻は、日付ではなく時点の値オブジェクトで受ける。日付が要る判断（返却期限の日）は、集約が時点から導く。

資料は `本を借りる(利用者番号, 資料番号, 貸出日, 貸出状況)` と書き、Go は `FindPendingLoan(ctx, user, book)` と `Borrow(loanID, lentAt)` になる。

集約の外の事実の写しは、初期状態の型だけが持ち、保存された状態の型へは引き継がない。それは借りる瞬間の写しで、貸出の状態ではないからである。

入力だけで初期状態を作れるコマンド（集約の外の事実が要らない生成）では、Find を置かず、usecase が初期状態の型を直接作る。

# イベントが持つ値

イベントの業務上の意味と、業務の時刻を引数で受けるかどうかは、ドメインモデルの資料が決める。イベントが持つ値の列は、データモデルの資料のイベント表の列が決める。Go のイベントの型は、この二つから写す。

業務の時刻を引数で受けるコマンドのイベントは、その時点を持つ。それが出来事の時点になる。業務の時刻を受けないコマンドのイベントは、時刻を持たない。出来事の時点は、リポジトリが記録のときに Clock から取る。

# 写さないもの

**提案の段階のもの。** ドメインモデルが業務知識への提案に回したもの（まだ業務知識に無い用語や拒む理由）は、まだ根拠ではない。書かずに止まり、提案が確定するのを待つ。書かないと型が閉じないとき（和型のメソッドの拒む理由が無い）は、そのコマンドを和型に置かない。そのコマンドを使う usecase も書かない。

**未決のもの。** 資料が未決としたものは、既定値や `TODO` で埋めない。資料が「仮に〜とする」と仮置きを明示したものは、その仮置きどおりに書き、報告で仮置きであることを示す。

**資料に無いもの。** 資料に無いコマンド、状態、拒む理由を作らない。「あると便利」「対称性のため」は理由にならない。資料に無くても置いてよいのは、復元の `Restore<状態名>`、呼び手が実際にある値の取り出しの関数、コマンドの結果の型、イベントの版だけである。
