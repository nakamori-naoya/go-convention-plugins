# 単位と命名

**対象（1つのメソッド・1つの関数）1つにつき、テスト関数は1つ。2つ以上作らない。** テスト関数が割れると「どこにケースを足すか」が毎回判断になり、同じケースが両方に書かれるか、どちらにも書かれなくなる。対象1つ・テスト関数1つ・テーブル1つの対応があるから、「このメソッドのケースは全部ここにある」と言える。どの対象にテストを持つかは層別の規約が決める。

## 1. テスト関数名

| 対象 | 名前 | 例 |
|---|---|---|
| メソッド | `Test{型}_{メソッド}` | `TestStack_Pop` |
| コンストラクタ | `Test{関数}` | `TestNewNumberSequence` |
| 関数 | `Test{関数}` | `TestFindPairSummingTo` |
| ベンチマーク | `Benchmark{型}_{メソッド}` / `Benchmark{関数}` | `BenchmarkStack_Pop` |

- アンダースコアは型名とメソッド名の間だけ
- サフィックスを付けない。`_EdgeCases` / `_Error` / `_Complexity` は2つ目のテスト関数であり禁止
- 状態ごとに分けた型（`ActiveReservation` / `CancelledReservation`）は別の型なので、それぞれにテスト関数を持つ
- `Benchmark*` はケース表を持たない。対象1つに1つで、入力を固定する

## 2. パッケージとファイル

| 項目 | 規則 | 理由 |
|---|---|---|
| パッケージ名 | `{pkg}_test`（外部テストパッケージ） | 実装と同じパッケージにいるとプライベートに手が届く。届かない場所に置く |
| ファイル名 | `{本体ファイル名}_test.go` | 対象とテストが1対1で並ぶ。`helper_test.go` のような任意名を作らない |
| import | 対象パッケージを通常の import で読む | 外から見える API だけを叩く |

## 3. プライベートをテストしない

`{pkg}_test` にいる時点でプライベート関数・メソッド・非公開フィールドには手が届かない。これは制約ではなく目的である。**公開 API だけをテストしていれば、内部を丸ごと書き換えてもテストは緑のまま**でいられる。

| プライベートをテストしたくなったとき | する |
|---|---|
| 内部関数が複雑で単体で確かめたい | 公開 API を通して観測できる振る舞いに翻訳する。翻訳できないなら、その関数は別パッケージの公開関数にする |
| 内部状態を見たい | 公開クエリ（`Len()` / `IsEmpty()`）で観測する。無いなら型に問い合わせが足りない |
| `export_test.go` で内部を晒したい | 使わない。外部テストパッケージにした意味が消える |

## 4. `*_test.go` に置くもの

**ファイルスコープに置くのは `Test*` / `Benchmark*` と、`const` だけ。** 表を支える型（`fixture` / `opKind` / `op` / `step` と種別定数）はテスト関数の中で宣言する。`{pkg}_test` は1つの名前空間なので、ファイルスコープに型を置くと2つ目のテスト関数で `fixture` が衝突する。関数の中なら、テスト関数ごとに同じ名前で持てる。

`const` だけは例外にする。同じ package の複数のテストで同じ意味の固定値（利用者番号、UUID）を使うとき、文字列を繰り返さずに名前を付けるためである。`const` は値を変えられず、ケースの間の依存を作らない。`var` は置かない。

**テスト関数の中に置く関数は、ループ本体の中の局所クロージャだけ**（[examples.md](examples.md) §2 の `run`）。表の前に関数を置かない。表の前に置いた関数はケースから参照され、ファイルスコープのヘルパーと同じものになる。

| 置かない | 代わりに |
|---|---|
| セットアップ・生成・検証のヘルパー関数、汎用のアサーション関数 | テストデータは Builder（[テストデータ](test-data.md)）、実 DB の基盤は共有のテスト支援 package（[実 DB](real-database.md)）へ出す |
| パッケージ変数 | `setup` が資源を取得し `t.Cleanup` で返す（[given.md](given.md) §2）。実 DB だけは `main_test.go` の共有の基盤が持つ |
| `TestMain` | 実 DB を使う package だけが、`main_test.go` に1つ置く（[実 DB](real-database.md)）。他のファイルには置かない |
