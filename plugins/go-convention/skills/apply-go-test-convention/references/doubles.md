# 差し替えてよい境界

# 差し替えてよいのは三つだけ

テストで差し替えてよいのは、**制御できない外部の境界、時計、採番**の三つだけである。これは層に依らない。集約、リポジトリ、usecase、handler のテストでも、interceptor、購読したメッセージを受け取る処理、ワーカーが定期的に対象を探す処理（巡回）、Outbox から要求を取り出して外部へ送る処理のテストでも、同じ規則を当てる。

制御できない外部の境界とは、このサービスの外にあり、テストの中で望む状態を作れない相手である。外部の API、メッセージの配信基盤への発行、認証基盤のトークンの検証がこれに当たる。時計は、テストの中で「今」を決めるために差し替える。採番は、生成される識別子を期待の値に書くために差し替える。

それ以外は、本番の組み立ての関数で実物を使う。同じプロセスの usecase、リポジトリ、Query の実装、トランザクションの管理、interceptor、logger、認可の方針の表を、偽物や mock に置き換えない。PostgreSQL は、dockertest で起動した実物を使う（[実 DB](real-database.md)）。

内部の部品を差し替えると、本番の組み立ての誤り（並べる順、渡し忘れ、tx の張り忘れ）を、テストが通してしまう。mock の呼び出しの回数を期待にすると、振る舞いではなく実装の手順を固定することになり、内部を書き換えるたびにテストが壊れる。

# 差し替え方

差し替えには、そのポートの interface から `go.uber.org/mock/mockgen` で生成した gomock を使う。生成は、interface のファイルに置いた `go:generate` で行い、生成先は所有する package の直下の `mock` package である。手書きの偽物（固定の時計、連番の採番器、インメモリのリポジトリ）を作らない。

```go
ctrl := gomock.NewController(t)
clk := mock_clock.NewMockClock(ctrl)
clk.EXPECT().Now().Return(time.Date(2026, 10, 16, 9, 0, 0, 0, time.UTC)).AnyTimes()
```

外部サービスを模した stub のサーバー（`httptest` で外部の API を立てる）は作らない。stub のサーバーが要ると感じたら、ポートの切り方を疑う。外部の境界のポートは、使う側が必要とする操作（鍵の集合を取る、トークンを検証する、外部の口座を照会する）の単位で小さく切り、その interface を gomock で差し替える。

テストで失敗をどう起こすか（失敗の注入）の原則は、この規約が持つ。実物で起こせる失敗は、実物を壊れた状態にして起こす。DB の制約の違反、行が無いこと、古い版での更新は、実 DB の前提データで起こせる。実物で起こせない失敗（外部の配信基盤の一時的な不在）だけを、ポートの mock が返す。

# API のテストの組み立て

API のテストは、本番と同じ組み立ての関数で handler を起動し、生成したクライアントから叩く。interceptor の列（記録、認証、認可、頻度の制限）は本番と同じに組む。差し替えるのは、外部の認証基盤のトークンを検証するポートと、時計と採番だけである。認可の interceptor そのものを差し替えると、すべての API のテストが本番の認可（ヘッダから操作の主体を特定すること、どの主体がどの RPC を呼べるかを定めた方針の表）を通らなくなる。

# 差し替えの確かめ方

テストが差し替えているのが三つの境界だけであることは、テストのコードで `mock_` の package を import している箇所を読んで確かめる。どの interface が差し替えてよい境界かは repository ごとに違うので、機械の検査にするなら、その repository が許可の一覧を持つ。
