# sqlc と tx

**SQL は sqlc の query ファイルにだけ書き、生成された `sqlcgen.Queries` を ctx の `pgx.Tx` から作って直接呼ぶ。** リポジトリは tx を張らない。usecase が `tx.Manager.Run(ctx, fn)` で張り、`pgx.Tx` を ctx に載せて `fn` を呼ぶ。リポジトリは `tx.From(ctx)` で取り出し、無ければ error を返す。

前提: `github.com/jackc/pgx/v5`、`github.com/sqlc-dev/sqlc`（`sql_package: "pgx/v5"`）。`database/sql` は使わない。

## 1. `sqlc.yaml`

```yaml
version: "2"
sql:
  - engine: "postgresql"
    schema: "rdb/schema"
    queries: "rdb/query"
    gen:
      go:
        package: "sqlcgen"
        out: "rdb/sqlcgen"
        sql_package: "pgx/v5"
        overrides:
          # NOT NULL の timestamptz は time.Time。NULL 許可列はこの override に当たらず pgtype.Timestamptz のまま
          - db_type: "timestamptz"
            go_type: "time.Time"
```

| 項目 | 規則 | 理由 |
|---|---|---|
| `sql_package` | `pgx/v5` | `pgx.Tx` をそのまま `DBTX` に渡せる。`database/sql` を経由しない |
| Params / 結果 | 値（ポインタにしない。`emit_params_struct_pointers` / `emit_result_struct_pointers` は既定の false） | marshaller が値を返し、nil 検査が要らない |
| override | NOT NULL の `timestamptz` → `time.Time` | NOT NULL 列に `pgtype` が現れず、`Valid` の検査を書かずに済む。NULL 列だけ `pgtype` で残り、[marshaller.md](marshaller.md) §5 の `(T, bool)` に写す |
| 生成物 | `rdb/sqlcgen` にコミットする。手で編集しない | `go build` が sqlc の実行に依存しない |
| `schema` | DDL の置き場を指すだけ。マイグレーションの道具はここで決めない | 上位の開発規約の関心 |

## 2. query ファイル

| 項目 | 規則 |
|---|---|
| 置き場 | `rdb/query/{aggregate}.sql`。集約 1 つに 1 ファイルで、その集約が触る全テーブルの query を持つ。テーブルごとに分けない |
| 名前 | `{Get\|Insert\|Update\|Delete}{Table 単数形}[目的]`。`GetReservation` / `InsertReservationBaseEvent` / `UpdateReservationCurrent` / `DeleteTentativeHoldDeadline` |
| 注釈 | 1 行読む `:one`、書くだけ `:exec`、更新行数で競合を見る `:execrows`、`RETURNING id` は `:one`。`:many` は非ルートエンティティの子行を集めるときだけ |
| 引数 | 列名と同じ位置引数 `$n`。列名から取れない引数（照合キー）だけ `sqlc.arg(expected_version)` で名前を付ける |
| 読む列 | `SELECT *` で行の型（`sqlcgen.Reservation`）をそのまま受ける。列を絞って独自の Row 型を増やさない |
| テスト用の query | 全行読み取り・投入など、テストが使う query をこのファイルに足さない。置き場と形はテストの規約が決める |

題材の `rdb/query/reservation.sql`（`ApplyHeld` / `ApplyConfirmed` / `ApplyNoShowRecorded` / `FindByID` が使う分）:

```sql
-- name: GetReservation :one
SELECT * FROM reservations WHERE reservation_id = $1;

-- name: GetTentativeHoldDeadline :one
SELECT * FROM tentative_hold_deadlines WHERE reservation_id = $1;

-- name: ListReservationNoShowRecordedAt :many
-- 確定済みの復元に使う。無いことが正常なので :many（0 件か 1 件）。reservation_no_show_recorded_events は資料に無い仮定の 9 表目
SELECT e.occurred_at
FROM reservation_base_events e
JOIN reservation_no_show_recorded_events n ON n.base_event_id = e.id
WHERE e.reservation_id = $1
ORDER BY e.version;

-- name: InsertReservation :exec
INSERT INTO reservations (reservation_id, room_code, customer_code, starts_at, ends_at, status, current_version, created_at, updated_at)
VALUES ($1, $2, $3, $4, $5, $6, $7, $8, $9);

-- name: UpdateReservationCurrent :execrows
UPDATE reservations
SET status = $2, current_version = $3, updated_at = $4
WHERE reservation_id = $1 AND current_version = sqlc.arg(expected_version);

-- name: InsertRoomBookingClaim :exec
INSERT INTO room_booking_claims (reservation_id, room_code, starts_at, ends_at, created_at)
VALUES ($1, $2, $3, $4, $5);

-- name: InsertTentativeHoldDeadline :exec
INSERT INTO tentative_hold_deadlines (reservation_id, expires_at, created_at)
VALUES ($1, $2, $3);

-- name: DeleteTentativeHoldDeadline :exec
DELETE FROM tentative_hold_deadlines WHERE reservation_id = $1;

-- name: InsertReservationBaseEvent :one
INSERT INTO reservation_base_events (reservation_id, event_type, version, actor_code, occurred_at)
VALUES ($1, $2, $3, $4, $5)
RETURNING id;

-- name: InsertReservationTentativeCreatedEvent :exec
INSERT INTO reservation_tentative_created_events (base_event_id, room_code, customer_code, starts_at, ends_at, expires_at)
VALUES ($1, $2, $3, $4, $5, $6);

-- name: InsertReservationConfirmedEvent :exec
INSERT INTO reservation_confirmed_events (base_event_id) VALUES ($1);

-- name: InsertReservationNoShowRecordedEvent :exec
INSERT INTO reservation_no_show_recorded_events (base_event_id) VALUES ($1);
```

生成されるシグネチャ（sqlc が決める。引数が 1 つなら Params struct は生まれず、読む列が 1 つなら Row 型も生まれない）:

```go
func (q *Queries) GetReservation(ctx context.Context, reservationID string) (Reservation, error)
func (q *Queries) ListReservationNoShowRecordedAt(ctx context.Context, reservationID string) ([]time.Time, error)
func (q *Queries) UpdateReservationCurrent(ctx context.Context, arg UpdateReservationCurrentParams) (int64, error)
func (q *Queries) InsertReservationBaseEvent(ctx context.Context, arg InsertReservationBaseEventParams) (int64, error)
func (q *Queries) InsertReservationConfirmedEvent(ctx context.Context, baseEventID int64) error
```

イベント表の `id` は `bigint generated by default as identity` を仮定し、`RETURNING id` で受ける。資料の論理型 `identifier` をどの物理型に写すかは物理設計が決めるので、実装時は DDL に従う。

## 3. 生成コードの使い方

- `sqlcgen.New(tx)` で `*sqlcgen.Queries` を作り、生成メソッドをそのまま呼ぶ。`Queries` を包む独自の型・interface を作らない（sqlc への密結合は許容する）
- `Queries` はメソッド呼び出しごとに作ってよい軽い構造体で、リポジトリの struct に持たない。持つと ctx の tx と食い違う
- SQL 文字列をリポジトリの Go ファイルに書かない。`pgx.Tx.Exec` / `Query` を直接呼ばない

## 4. tx

usecase が張る。リポジトリは乗るだけ。

```go
package tx

import (
	"context"
	"errors"
	"fmt"

	"github.com/jackc/pgx/v5"
	"github.com/jackc/pgx/v5/pgxpool"
)

type ctxKey struct{}

type Manager struct{ pool *pgxpool.Pool }

func NewManager(pool *pgxpool.Pool) *Manager { return &Manager{pool: pool} }

// Run は tx を張り、pgx.Tx を載せた ctx で fn を呼ぶ。fn が error を返せば rollback、返さなければ commit。
// 返す error は fn の error そのもの（errors.Is が通る）で、rollback が失敗したときだけ errors.Join で束ねる。
// 呼ぶのは usecase で、その書き方は usecase の規約が決める。
func (m *Manager) Run(ctx context.Context, fn func(ctx context.Context) error) (err error) {
	t, err := m.pool.Begin(ctx)
	if err != nil {
		return fmt.Errorf("トランザクションの開始: %w", err)
	}
	defer func() {
		if err == nil {
			return
		}
		// commit を試みた後の Rollback は ErrTxClosed を返す。それは失敗ではないので束ねない
		if rbErr := t.Rollback(ctx); rbErr != nil && !errors.Is(rbErr, pgx.ErrTxClosed) {
			err = errors.Join(err, rbErr)
		}
	}()
	if err := fn(context.WithValue(ctx, ctxKey{}, t)); err != nil {
		return err
	}
	if err := t.Commit(ctx); err != nil {
		return fmt.Errorf("トランザクションのコミット: %w", err)
	}
	return nil
}

// From は ctx に載った pgx.Tx を返す。無ければ false。
func From(ctx context.Context) (pgx.Tx, bool) {
	t, ok := ctx.Value(ctxKey{}).(pgx.Tx)
	return t, ok
}
```

リポジトリ側は全メソッドの先頭で `queries(ctx)` を呼ぶ。

```go
package rdb

import (
	"context"

	"example.com/roomflow/rdb/sqlcgen"
	"example.com/roomflow/tx"
)

// queries は ctx の tx から sqlc の Queries を作る。tx が無ければ ErrNoTransaction。
func queries(ctx context.Context) (*sqlcgen.Queries, error) {
	t, ok := tx.From(ctx)
	if !ok {
		return nil, ErrNoTransaction
	}
	return sqlcgen.New(t), nil
}
```

| 規則 | 理由 |
|---|---|
| `Run` は名前付き結果を持ち、`defer` で rollback の失敗を `errors.Join` で fn の error に束ねる。`_ = t.Rollback(ctx)` で捨てない | rollback の失敗（接続断）は fn の失敗と独立した事実で、捨てると境界のログから消える。`errors.Is` は `Join` の中も探すので、usecase と境界の sentinel 判定は変わらない |
| commit 後の `Rollback` が返す `pgx.ErrTxClosed` は束ねない | commit が失敗しても tx は閉じていて、rollback するものが無い。「閉じている」を失敗として重ねると、原因（commit の失敗）が読みにくくなる |
| tx が無ければ `ErrNoTransaction` を返す。pool へ素通りしない | `Apply*` は複数テーブルに書く。tx の外で動くと途中失敗が部分的に残る。素通りすると usecase の `Run` の書き忘れが本番まで見つからない |
| `FindByID` も同じ。読み取りでも tx を要求する | usecase は `FindByID` → 操作 → `Apply*` を同じ tx で行う。読み取りだけ pool を使う経路を作ると、規則が「書き込みなら」の条件付きになる |
| リポジトリは `Begin` / `Commit` / `Rollback` を呼ばない。`SAVEPOINT` も切らない | 境界は usecase 1 か所 |
| `pgx.Tx` を引数・返り値・struct のフィールドに出さない | ctx だけが運ぶ。interface に DB の型が漏れない |
| `ErrNoTransaction` は `rdb` package の sentinel（[error-translation.md](error-translation.md) §1） | 業務の拒否ではなく組み立ての誤りなので、境界では Internal になる |
