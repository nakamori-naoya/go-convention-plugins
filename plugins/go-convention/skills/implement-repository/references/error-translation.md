# エラー翻訳

**DB が拒んだ事実は、リポジトリの中でドメインの言葉か `rdb` の sentinel に翻訳して返す。** `pgconn.PgError` と `pgx.ErrNoRows` を見るのはリポジトリだけで、usecase と境界は `errors.Is` で sentinel を判定する。翻訳表に無いものは翻訳せず、文脈を 1 回足してそのまま返す。

## 1. 翻訳の 3 種

| DB が返すもの | 翻訳先 | 誰の sentinel か | 境界での扱い |
|---|---|---|---|
| 制約違反（排他 `23P01` / 一意 `23505`）で、資料の「常に守られること」に対応する制約 | ドメインの sentinel（`reservation.ErrOverlappingSlot`） | ドメイン（資料「拒むときの理由」と 1:1） | 業務の拒否（FailedPrecondition 等） |
| `pgx.ErrNoRows`（`FindByID` の `:one`） | `rdb.ErrNotFound` | `rdb` | NotFound |
| 楽観ロック付き UPDATE の 0 行（イベント型） | `rdb.ErrConflict` | `rdb` | Aborted |
| 一意制約 `reservation_base_events_reservation_id_version_uniq`（`(reservation_id, version)`）の違反（イベント型） | `rdb.ErrConflict` | `rdb` | Aborted |
| 主キー指定 UPDATE の 0 行（通常型。版なし） | `rdb.ErrNotFound` | `rdb` | NotFound |
| ctx に tx が無い | `rdb.ErrNoTransaction` | `rdb` | Internal（組み立ての誤り） |
| 上のどれでもない（接続断・翻訳表に無い制約違反・FK 違反・行の VO 復元失敗） | 翻訳しない。文脈を足して返す | — | Internal |

`rdb` package の sentinel:

```go
package rdb

import "errors"

var (
	ErrNotFound      = errors.New("対象が見つからない")
	ErrConflict      = errors.New("対象が別の操作で更新された")
	ErrNoTransaction = errors.New("トランザクションの外ではリポジトリを呼べない")
)
```

文言は日本語・句点なし・何が拒まれたか。`ErrNotFound` は集約名を入れない（`rdb` は複数の集約のリポジトリを持ち、どの集約かは呼び手が足す文脈が言う）。ドメインの sentinel は集約の package が持ち、リポジトリは定義しない。

## 2. 制約違反 → sentinel

`errors.AsType[*pgconn.PgError]` で SQLSTATE と制約名を見て、制約名 → sentinel の表で翻訳する。表は `rdb/errors.go` に 1 つ。翻訳先は 2 種で、資料の不変条件を表す制約はドメインの sentinel、版の一意制約（イベント型の楽観ロックの最後の砦）は `rdb.ErrConflict`。

```go
package rdb

import (
	"errors"

	"github.com/jackc/pgx/v5/pgconn"

	"example.com/roomflow/reservation"
)

// PostgreSQL の SQLSTATE。制約違反（クラス 23）だけを見る。
const (
	sqlstateUniqueViolation    = "23505"
	sqlstateExclusionViolation = "23P01"
)

// translateConstraint は、制約違反を sentinel に翻訳する。
// 資料の不変条件を表す制約はドメインの sentinel、版の一意制約は ErrConflict。
// 表に無い制約違反と、制約違反でない error はそのまま返す。
func translateConstraint(err error) error {
	pgErr, ok := errors.AsType[*pgconn.PgError](err)
	if !ok {
		return err
	}
	switch pgErr.Code {
	case sqlstateExclusionViolation:
		if pgErr.ConstraintName == "room_booking_claims_no_overlap" {
			return reservation.ErrOverlappingSlot
		}
	case sqlstateUniqueViolation:
		if pgErr.ConstraintName == "reservation_base_events_reservation_id_version_uniq" {
			return ErrConflict
		}
	}
	return err
}
```

翻訳する制約は DDL で名前を付ける。自動生成名（`room_booking_claims_room_code_excl` / `reservation_base_events_reservation_id_version_key` 等）に依存しない。

```sql
CREATE TABLE room_booking_claims (
    reservation_id text PRIMARY KEY REFERENCES reservations (reservation_id),
    room_code      text NOT NULL,
    starts_at      timestamptz NOT NULL,
    ends_at        timestamptz NOT NULL,
    created_at     timestamptz NOT NULL,
    CONSTRAINT room_booking_claims_no_overlap
        EXCLUDE USING gist (room_code WITH =, tstzrange(starts_at, ends_at, '[)') WITH &&)
);

CREATE TABLE reservation_base_events (
    id             bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    reservation_id text NOT NULL REFERENCES reservations (reservation_id),
    event_type     text NOT NULL,
    version        integer NOT NULL,
    actor_code     text NOT NULL,
    occurred_at    timestamptz NOT NULL,
    CONSTRAINT reservation_base_events_reservation_id_version_uniq UNIQUE (reservation_id, version)
);
```

| 規則 | 理由 |
|---|---|
| 翻訳先は sentinel そのもの。`PgError` を `%w` で残さない | 制約名で「何が拒まれたか」は確定している。SQLSTATE の詳細は境界が使わない |
| 制約名で分岐する。SQLSTATE だけで分岐しない | 同じ `23505` でも、主キー重複（組み立ての誤り）と版の一意（競合）と業務の一意（資料の不変条件）は別物 |
| 表に無い制約違反は翻訳しない | 主キー重複・FK 違反は業務の拒否ではない。既定の sentinel へ丸めると、バグが業務エラーとして返る |
| 翻訳表は `rdb` に 1 つ。集約ごとに分けない | 制約名は DB 全体で一意。表が 1 つなら重複と漏れが読める |
| 版の一意制約違反は `ErrConflict`。current 行の UPDATE 0 行と同じ sentinel | どちらも「同じ予約に別の操作が先に適用された」という 1 つの事実。境界の対応表は 1 行で足りる |
| `INSERT` / `UPDATE` / `DELETE` の error に `translateConstraint` を通す。`SELECT` には通さない | 制約違反は書き込みでしか起きない。UPDATE も CHECK・FK・一意に当たりうるので通す |
| 資料の不変条件を DDL の制約で表せるのに DDL に無いなら、リポジトリで `SELECT` して判断しない | 同時実行では `SELECT` の後に割り込まれる。データモデル資料へ返す（停止条件） |

## 3. `ErrNoRows` と 0 行

```go
	res, err := q.GetReservation(ctx, id.Value())
	if err != nil {
		if errors.Is(err, pgx.ErrNoRows) {
			return nil, fmt.Errorf("予約 %s の取得: %w", id.Value(), ErrNotFound)
		}
		return nil, fmt.Errorf("予約 %s の取得: %w", id.Value(), err)
	}
```

```go
	rows, err := q.UpdateReservationCurrent(ctx, eventToUpdateReservationCurrentParams(evt, statusConfirmed))
	if err != nil {
		return fmt.Errorf("予約 %s の確定の保存: %w", id, translateConstraint(err))
	}
	if rows == 0 {
		return fmt.Errorf("予約 %s の確定の保存: %w", id, ErrConflict)
	}
```

| 場面 | 翻訳 | 理由 |
|---|---|---|
| `FindByID` の `:one` が `pgx.ErrNoRows` | `ErrNotFound` | 指した ID の集約が無い |
| 必須の従属行（仮押さえ中の `tentative_hold_deadlines`）の `:one` が `ErrNoRows` | 翻訳しない | current 行と従属行の不整合はデータ破損。「無い」と返すと usecase が NotFound として扱う |
| 任意の従属行（確定済みの無断不利用の記録）が 0 行 | error にしない。`:many` で読み、0 行は「起きていない」 | 無いことが正常な行は `:one` で読まず、`ErrNoRows` を「無い」に読み替える分岐を作らない |
| イベント型の楽観ロック付き UPDATE が 0 行 | `ErrConflict` | usecase が同じ tx で `FindByID` 済みで、行は消えない。0 行の原因は版の不一致だけ |
| イベント型の基底イベント INSERT が版の一意制約違反 | `ErrConflict`（§2） | UPDATE を先に置くので通常はそこで止まる。一意制約は UPDATE を経ない経路（初回の `ApplyHeld` の重複・組み立ての誤り）に対する最後の砦 |
| 通常型の主キー指定 UPDATE が 0 行 | `ErrNotFound` | 版が無いので競合は検出できない。行が無いことだけが分かる |
| `:exec` / `:execrows` の INSERT / UPDATE / DELETE が制約違反 | §2 | — |

## 4. 文脈の足し方

層境界で `fmt.Errorf("予約 %s の保存: %w", id, err)` の形で 1 回だけ足す。

| 規則 | 理由 |
|---|---|
| 1 メソッドの中で `%w` は 1 段。marshaller の error にも sentinel にも、メソッドが 1 回だけ足す | 同じ ID が何段にも重なる文言を作らない |
| 文脈は「対象 ID ＋ 何をしていたか」。SQL 文・テーブル名・SQLSTATE を文言に入れない | 境界がログに出す文言に DB の内部を漏らさない |
| sentinel を返すときも文脈を足す（`fmt.Errorf("...: %w", id, ErrConflict)`） | `errors.Is` は包んでも通る。文脈が無いと、どの集約のどの操作で競合したかが境界で分からない |
| `errors.Join` を使わない | リポジトリの失敗は 1 つの query の失敗で、独立した複数失敗ではない |
| ログを書かない。`log/slog` を import しない | 返した error を境界が 1 回記録する |
| error を握りつぶさない。既定値へ丸めない。panic しない | 返り値は `error` か `(T, error)` の 2 つまで |
