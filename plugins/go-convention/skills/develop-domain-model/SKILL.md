# develop-domain-model

中心にあるのは二つの考えである。**業務の操作を受けるか拒むかはコマンドが決め、値と状態が資料の意味を満たすことはそれを作る入口が守る。** 値オブジェクトも集約の状態も、成立に必要な材料を一つの生成入口で揃え、成功時には完全な値だけを返す。生成・遷移・復元で成立条件を変えず、部分的な値を後から setter で完成させない。型の名前や非公開フィールドだけでは、その条件を満たした証拠にならない。初期状態を含め、コマンドは判断する状態の型のメソッドにし、その型が判断の材料を持つ。そうすれば usecase は、集約を見つけ、コマンドを一回呼び、結果を適用するだけで書ける。**資料が決め、コードはそれを写す。** 欠けた資料が結論を変える単位は書かずに持ち主へ返し、独立して決まる単位は進める。

進め方と赤は development-convention の `develop-inside-out` に、言語の形は write-go-code、エラーは handle-errors、テストの共通の形は apply-go-test-convention に従う。名前、状態、コマンド、拒む理由は対象の資料から決める。

## 資料をどう読むか

ドメインモデルは境界、判断の持ち主、重要な値の関係を議論した叩き台として読む。`<<集約ルート>>` などの種別は型の候補を示すが、図にすべての要素、コマンド、引数、状態遷移があるとは仮定しない。実装する行い、その条件と拒む理由、結果、状態ごとの受け方は業務知識のBDDと規則から読み、保存した結果に要る値はコマンドデータモデルとも照合する。ドメインモデルの採用案と業務知識が食い違うなら、どちらかを黙って修正せず持ち主へ返す。業務知識に無い拒む理由は作らない。

コマンドの引数のうち、集約の外の事実の写しとそれを読む識別子は、判断する状態の型が持ち、リポジトリの Find が読んで持たせる。外の事実は保存された集約の値と区別し、次のコマンドで使うときはその時点の値に更新する。発行した ID はメソッドの引数に残す。時刻を引数と状態に置くかは development-convention の `apply-layer-convention` の基準で決め、置く時刻は日付ではなく時点の値オブジェクトで受ける。時点を暦へ変えるタイムゾーンのような設定値は、それを持つ値オブジェクトを組み立ての場所が一度だけ作って引数で渡し、ドメインは既定のタイムゾーンを読まない。材料の要らない生成では Find を置かず、usecase が初期状態の型を作る。

提案の段階のもの（ドメインモデルが業務知識への提案に回したもの）と未決のものは写さない。例外は、保存した集約を見分ける識別子が提案に回っているときだけで、それが無いと何も書けないので提案の語で仮置きし、報告で示す。資料に無い業務上の状態や行いは足さない。完全な状態を作るための非公開の初期型や中間表現、`Restore<状態名>`、呼び手がいる値の取り出しの関数、コマンドの結果の型は実装上の形として置ける。初期型を保存後も再開できる業務上の下書きとして扱うなら、その意味は業務知識の持ち主へ返す。

## 集約の形

まだ保存されていない集約は**初期状態の型**で表し、版を持たせない。共通の struct や interface を通しても版を持ち込まず、版0のような特別な値を作らない。保存されていないことを型が表すからである。判断材料がある初期状態は具象型を非公開にし、`New*` か Find が必要な値を揃えて作る。材料が無ければ空の型で足りる。保存された状態の版は、コマンドデータモデルや物理設計がその集約の版を要求するときに持つ。図の終端が保存される状態かどうかは資料が決める。

保存された状態の型の和は、非公開のメソッドを一つ持つ interface で閉じ、`//sumtype:decl` を付ける。**和型は、保存された状態が受けうるすべてのコマンドを持つ。** 具象の保存状態を非公開にし、完全に組み立てた値だけを和型で返す。新しい実装を外から足せないだけでなく、外から保存状態のゼロ値を作って復元時の不変条件を迂回できない公開面にする。受けるか拒むかは状態ごとの型が決め、受けない状態は資料の拒む理由を返す。こうすると usecase は状態を調べずにコマンドを呼べ、コマンドを足すと全部の状態で決めるまでコンパイルが通らない。受けない状態の拒む理由が資料に無ければ、そのコマンドは和型に置かず、それを使う usecase も書かずに資料へ返す。どの状態でも変わらない値は、業務の言葉で名付けた非公開の struct にまとめて埋め込み、同じ振る舞いは非公開の関数に一つだけ書く。

生成と保存済み状態からの遷移を一つのコマンドが兼ねる集約では、初期状態の型も和型に入れる。Find は、行が無ければ判断材料を持つ初期状態の型を、あれば保存された状態の型を返す。行の有無によってコマンドを受けるか拒むかは状態の型が決める。呼び手が行の有無を見て拒むと、業務の判断が usecase へ漏れるからである。

コマンドは状態の型の値レシーバのメソッドで、結果と error を返す。結果は資料にある次の保存状態とイベントを表す。イベントを結果として返しても、履歴として保存するとは限らない。次状態をそのまま次のコマンドへ使うなら判断材料を欠かさず、外の事実が変わる場合は次のコマンドの前に取り直す。資料が版を要求するときは、コマンドが版を一つ進め、次の保存状態とイベントの必要な方へ渡し、生成は版1を渡す。事前条件は資料の順に確かめて最初に破れた理由を返し、順が決まっていなければ仮置きして報告する。「〜の状態である」という条件はメソッドがその型にあることで満たされるので `if` を書かない。拒まないが何も変えないことがあるコマンドは `(Result, bool)` を返す。判断だけの公開メソッドは置かない。呼ぶ側が先に判断する形は、業務の判断を usecase へ漏らすからである。コマンドの事前条件はコマンドが判断し、保存状態の必須値と関係は状態ごとの非公開の生成入口で守る。コマンドの次状態も `Restore<状態名>` も同じ成立条件を通して完全な状態だけを返す。後者は保存値だけで判定できない外部の事実を再判定しない。呼ぶのはリポジトリとテストだけである。ドメインは時計を持たず ID の発行もせず、業務の数は非公開の定数にする。

## 値オブジェクト、イベント、永続化ポート

値オブジェクトは非公開フィールドの struct を `New*` だけが必要な値を一度に受けて作り、値が一つでも `struct{ v string }` にする。拒む値があるときだけ `(X, error)` を返し、生成の中で正規化して（時点は `UTC()`）`==` で比べられる値にする。Go では公開された値型のゼロ値も渡せるので、集約の生成入口とコマンドは受け取った値が必須条件を満たすか確かめ、`New*` を経たはずだと仮定しない。`String()`、`LogValuer`、`MarshalJSON`、`Scan`、`Validate()` を実装しない。何を外へ出すかは、記録や変換をする行で決めるからである。識別子は型ごとに別の struct にし、ID ジェネレーターが発行した UUID をその場で変換する関数を置く。「〜から決まる値」は材料を受けて `New*` の中で決める。

イベントは資料のイベント一つに型一つで、名前はクラス図の英名にする。版は資料が要求するときに持ち、時刻は同じ基準でコマンドが判断に使った時点だけを持つ。値は業務資料とコマンドデータモデルから決め、取り出しの関数は呼び手が読むものだけにし、生成関数を公開しない。永続化ポートは集約と同じ package に一つ置き、完全な集約を返す `Find<返す型>` と、保存型に合う書き込みのメソッドを持たせる。イベント履歴を保存するなら `Apply<イベント名>` は error だけを返す。リソース中心なら資料が決めた現在の値を保存し、イベント表を要求しない。ドメインは `log/slog`、pgx、connect、JSON を import しない。

## テスト：判断だけを、メモリの上の値で確かめる

ドメインのテストが主に担うのは、`Then:` が、受けるか拒むか、次の状態、発するイベント、値の生成の条件を観測する BDD である。DB の制約が守る拒否と同時に起きたときは永続化の、本人の確認は入口のテストが主に担う。テスト関数は、生成のコマンドなら `Test<初期状態の型>_<コマンド>`、和型のコマンドなら状態の型ごとの `Test<状態の型>_<コマンド>` にし、受けない状態のテストにその状態で拒む BDD を置く。

Given は初期状態の型と `Restore*` と `New*` に渡す値で、資料の `Given:` に現れない引数（識別子、版）は表の前で一度だけ作る。When はコマンドの引数、Then は資料どおりの次状態を `Restore*` で組んだ `wantNext`、イベントから取り出した値を並べた `wantEvent`、`wantErr` である。生成直後と復元後の両経路で同じ不変条件を確かめ、次状態から続く操作も通して、単発のコマンドだけでは見えない欠落を見つける。資料に無いケースは、具体エラーごと、境界の両側、理由を同時に破る組の順、`false` の側を足したら止める。値を取り出すだけのテストは書かない。資源を持たないので `t.Parallel()` をテスト関数とサブテストの両方に置く。

## 機械検査と止まるとき

```bash
gofmt -l ./<domain package>
go vet ./<domain package>/...
go tool golangci-lint run ./<domain package>/...
go test -shuffle=on -count=1 ./<domain package>/...
```

受けない状態の拒む理由が資料に無いとき、資料に無い業務コマンド、保存後の業務状態、拒む理由が要るとき、結果の値や保存型が資料から決まらないとき、提案の段階のものが要るとき、判断に要る時刻が時点で受けられないときは、その欠落で結論が変わる単位だけを書かずに資料へ返す。名前で止まるかは development-convention の `write-readable-code` の基準に従う。事前条件の順では止まらず、仮説を採って報告に示す。報告には、資料の要素と型の対応、止めたものと返し先、仮置きしたもの、主に担う BDD の ID を書く。
