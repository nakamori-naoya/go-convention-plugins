# develop-domain-model

中心にあるのは二つの考えである。**業務の判断はコマンドの中にだけ置く。** 状態で受けるか拒むかは状態の型が決め、判断の材料は初期状態の型が持つ。そうすれば usecase は、集約を見つけ、コマンドを一回呼び、結果を適用するだけで書ける。**資料が決め、コードはそれを写す。** 資料に無いものが要ると分かったら、書かずに資料へ返す。

進め方と赤は development-convention の `develop-inside-out` に、言語の形は write-go-code、エラーは handle-errors、テストの共通の形は apply-go-test-convention に従う。完全な例は [例：図書館の貸出](references/example.md) にあり、書き始める前に一度読む。写すのは形で、名前、状態、コマンド、拒む理由は対象の資料から取る。

## 資料をどう読むか

クラス図から要素と種類を読む。`<<集約ルート>>` は集約の型に、`<<値オブジェクト>>` は値オブジェクトに、`<<ドメインイベント>>` はイベントの型になり、`<<値オブジェクト・文脈共有>>` は共有の置き場に置く。集約ルートの操作の行からコマンドと引数を、状態遷移図から状態とコマンドの受け方を読む。状態一つが保存された状態の型一つになり、`[*]` から出るコマンドは初期状態の型が持つ。文からは図に無いもの（拒む理由と事前条件）だけを読み、拒む理由は業務知識の資料の拒む理由（`#### 拒む理由:` の見出し）だけを根拠にする。

コマンドの引数のうち、集約の外の事実の写し（利用者のほかの貸出から集めた貸出状況）とそれを読む識別子は、初期状態の型が持ち、リポジトリの Find が読んで持たせる。業務の時刻と採番した識別子はメソッドの引数に残し、時刻は日付ではなく時点の値オブジェクトで受ける。時点を暦へ変えるタイムゾーンのような設定値は、それを持つ値オブジェクトを組み立ての場所が一度だけ作って引数で渡し、ドメインは既定のタイムゾーンを読まない。材料の要らない生成では Find を置かず、usecase が初期状態の型を作る。

提案の段階のもの（ドメインモデルが業務知識への提案に回したもの）と未決のものは写さない。例外は、保存した集約を見分ける識別子が提案に回っているときだけで、それが無いと何も書けないので提案の語で仮置きし、報告で示す。資料に無くても置いてよいのは、`Restore<状態名>`、呼び手がいる値の取り出しの関数、コマンドの結果の型、版だけである。

## 集約の形

まだ保存されていない集約は**初期状態の型**で表し、版を持たせない。版0のような特別な値は作らない。保存されていないことを型が表すからである。保存された状態の型は、終端の状態も含めて版を持つ。

保存された状態の型の和は、非公開のメソッドを一つ持つ interface で閉じ、`//sumtype:decl` を付ける。**和型は、保存された状態が受けうるすべてのコマンドを持つ。** 受けるか拒むかは状態ごとの型が決め、受けない状態は資料の拒む理由を返す。こうすると usecase は状態を調べずにコマンドを呼べ、コマンドを足すと全部の状態で決めるまでコンパイルが通らない。受けない状態の拒む理由が資料に無ければ、そのコマンドは和型に置かず、それを使う usecase も書かずに資料へ返す。どの状態でも変わらない値は非公開の struct にまとめて埋め込み、同じ振る舞いは非公開の関数に一つだけ書く。

コマンドは状態の型の値レシーバのメソッドで、`<コマンド名>Result{Next; Event}` と error を返し、次の状態に操作が無くてもこの形を崩さない。版を一つ進めた値を `Next` と `Event` の両方へ渡し、生成は版1を渡す。版を決めるのはコマンドだけである。事前条件は資料の順に確かめて最初に破れた理由を返し、順が決まっていなければ仮置きして報告する。「〜の状態である」という条件はメソッドがその型にあることで満たされるので `if` を書かない。拒まないが何も変えないことがあるコマンドは `(Result, bool)` を返す。判断だけの公開メソッド（`CanBorrow`、`Validate`）は置かない。呼ぶ側が先に判断する形は、業務の判断を usecase へ漏らすからである。`Restore<状態名>` は検証せず、呼ぶのはリポジトリとテストだけである。ドメインは時計を持たず採番もせず、業務の数は非公開の定数にする。

## 値オブジェクト、イベント、永続化ポート

値オブジェクトは非公開フィールドの struct を `New*` だけが作り、値が一つでも `struct{ v string }` にする。拒む値があるときだけ `(X, error)` を返し、生成の中で正規化して（時点は `UTC()`）`==` で比べられる値にする。`String()`、`LogValuer`、`MarshalJSON`、`Scan`、`Validate()` を実装しない。何を外へ出すかは、記録や変換をする行で決めるからである。識別子は型ごとに別の struct にし、採番器の UUID をその場で変換する関数を置く。「〜から決まる値」は材料を受けて `New*` の中で決める。

イベントは資料のイベント一つに型一つで、名前はクラス図の英名にする。版を持ち、業務の時刻を受けるコマンドのイベントはその時点を持つ。持つ値の列はコマンドデータモデルのイベントの表から決め、取り出しの関数は Apply が読むものだけにし、生成関数を公開しない。永続化ポートは集約と同じ package に一つ置き、完全な集約を返す `Find<返す型>` と error だけを返す `Apply<イベント名>` だけにする。ドメインは `log/slog`、pgx、connect、JSON を import しない。

## テスト：判断だけを、メモリの上の値で確かめる

ドメインのテストが主に担うのは、`Then:` が、受けるか拒むか、次の状態、発するイベント、値の生成の条件を観測する BDD である。DB の制約が守る拒否と同時に起きたときは永続化の、本人の確認は入口のテストが主に担う。テスト関数は、生成のコマンドなら `Test<初期状態の型>_<コマンド>`、和型のコマンドなら状態の型ごとの `Test<状態の型>_<コマンド>` にし、受けない状態のテストにその状態で拒む BDD を置く。

Given は初期状態の型と `Restore*` と `New*` に渡す値で、資料の `Given:` に現れない引数（識別子、版）は表の前で一度だけ作る。When はコマンドの引数、Then は `Restore*` で組んで版だけを進めた `wantNext`、イベントから取り出した値を並べた `wantEvent`、`wantErr` である。資料に無いケースは、具体エラーごと、境界の両側、理由を同時に破る組の順、`false` の側を足したら止める。値を取り出すだけのテストは書かない。資源を持たないので `t.Parallel()` をテスト関数とサブテストの両方に置く。

## 機械検査と止まるとき

```bash
gofmt -l ./<domain package>
go vet ./<domain package>/...
go tool golangci-lint run ./<domain package>/...
go test -shuffle=on -count=1 ./<domain package>/...
```

受けない状態の拒む理由が資料に無いとき、資料に無いコマンド、状態、拒む理由が要るとき、提案の段階のものが要るとき、業務の時刻が時点で受けられないときは、書かずに資料へ返す。名前の揺れや事前条件の順では止まらず、仮説を採って報告に示す。報告には、資料の要素と型の対応、止めたものと返し先、仮置きしたもの、主に担う BDD の ID を書く。
