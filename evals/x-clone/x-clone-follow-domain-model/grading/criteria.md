# X のクローンのフォローに固有の条件

フォローの資料は、フォロー上限の判断に要るフォロー中の人数を集約の外の事実にし、同じ二人の重複と本人の確認を集約の外が守ると決めている。一件のフォローを見分ける識別子は、ドメインモデルが業務知識への提案に回している。作業の前の repository には、アカウントの業務が置いた利用者IDの値オブジェクトが `internal/shared/vo/id` にあった。

### follow-limit-in-command

重み: 3

PASS：フォロー上限（5,000人）の判断は、フォローするコマンドの中にあり、フォロー中の人数は集約の構造体か値オブジェクトが持つ値として渡される。4,999人で通り5,000人で拒むことを、テストが両側で確かめている。上限の数は非公開の定数である。

FAIL：上限の判断がコマンドの外（呼び手、判断だけの公開関数）にある。または、上限の数が公開されているか、境界の片側しか確かめていない。

### outside-rules-not-invented

重み: 2

PASS：資料が集約の外に置いた判断（すでにフォロー中の相手か、相手が存在するか、本人か）を、材料を持たないまま集約のコマンドで判定する形を作っていない。これらの拒む理由の具体エラーを定義したなら、ドメインのテストがそれを起こしたと名乗っていない。

FAIL：資料が集約の外に置いた判断を、集約のコマンドや値オブジェクトが、資料に無い材料を仮に持たせて判定している。

### identifier-proposal-handled

重み: 2

PASS：一件のフォローを見分ける識別子を置いたなら、資料の提案の語（フォローID）で置き、報告で提案からの仮置きであることを示している。置かなかったなら、それで何が書けないかを報告で示している。

FAIL：提案の語と違う名前で識別子を置いているか、提案からの仮置きであることを報告で示していない。

### reuse-shared-user-id

重み: 3

PASS：フォロワーとフォロー相手が指す利用者IDに、作業の前からあった `internal/shared/vo/id` の利用者IDを使っている。

FAIL：利用者IDを表す型を、別の package に新しく書いている。または、利用者IDを `string` や `uuid.UUID` のまま持っている。
